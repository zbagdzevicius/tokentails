# Track D — Community-governed funding

For DAO treasury proposals: Nouns DAO now, any DAO with a "candidate, then sponsor, then vote"
flow later. We don't hold voting power, so the job is to post a clean candidate, find one sponsor,
and **stop after the kill window** (default 21 days) if nobody sponsors it. The track makes that
kill rule mechanical: `fund check` fails once the window passes without a sponsor.

Files per application (on top of the shared call.md / draft.md / review.md / source.md):

| File | What it holds |
|---|---|
| `call.md` | Extra frontmatter: `dao`, `proposal_title`, `posted`, `kill_after_days`, `forum_url`, `eth_usd`, `budget_unit`, `min_budget`, `max_budget` |
| `draft.md` | Proposal sections: TL;DR, Motivation, Specification, Budget, Milestones & deliverables, Team, Risks, Why this DAO |
| `budget.md` | `\| Item \| Amount \| Currency \|`, ETH or USD (USDC counts as USD). Totals are computed, never typed |
| `sponsors.md` | `\| Date \| Who (role) \| Channel \| Ask \| Response \|`. Roles only, never emails or phones |
| `proposal.md` | Generated by `d:export`, the text you paste to the forum |

## The fast loop

```bash
cd funding/framework
node bin/fund.mjs new <slug> --track D --program "<DAO> proposal" --url <guidance-url>
# paste the DAO's proposal guidance into source.md, then (rewrites call.md; git diff it after):
node bin/fund.mjs prompt extract <slug> --run --out applications/<slug>/call.md
# fill budget.md, set dao / eth_usd / budget_unit / min_budget / max_budget in call.md, then:
node bin/fund.mjs prompt draft <slug> --run --out applications/<slug>/draft.md
node bin/fund.mjs check <slug>                         # citations, banned terms, budget bounds, PII
node bin/fund.mjs prompt review <slug> --run           # hostile reviewer, appended to review.md
node bin/fund.mjs d:export <slug>                      # proposal.md: sections + ETH/USD table + sponsor ask
# paste proposal.md to the forum as a candidate, then start the clock:
node bin/fund.mjs d:post <slug> --url <thread-url>     # sets posted = today (or --date), forum_url
node bin/fund.mjs d:export <slug>                      # closing line now has the withdraw date + thread; edit the post
node bin/fund.mjs d:log <slug> --who "Noun owner" --channel Discord --ask "Sponsor the candidate?" --response pending
node bin/fund.mjs d:clock <slug>                       # daily: CONTINUE / FIND SPONSOR / KILL
# when someone says yes: log it with --response yes, then
node bin/fund.mjs d:export <slug>                      # refreshes the closing line to "Sponsored"
node bin/fund.mjs status <slug> ready --next "Sponsor found; get it onchain"
node bin/fund.mjs check <slug>                         # must pass at ready (proposal.md present and current)
```

Without an AI command, fill call.md and draft.md by hand (copy from `applications/nouns-dao/`) and
skip the three `prompt` lines; every other step is the same.

`d:export` refuses to write (exit 1) when budget.md has a row it can't read, a hand-written total,
a decimal comma (`2,5`), or a total outside `min_budget`..`max_budget`, because the pasted ask would
be wrong. If anything else in `fund check` fails (limits, citations...) it writes proposal.md but
exits 1 and tells you not to paste it yet.

Every command prints the next one to run. Verdicts from `d:clock`:

| Verdict | Meaning | Next |
|---|---|---|
| NOT POSTED | `posted` is empty, clock not started | `d:export`, post, `d:post` |
| FIND SPONSOR | inside the window, no sponsor yet | ask someone, `d:log` |
| CONTINUE | a sponsor row exists: Response contains "yes" or "sponsor" ("yes", "sponsor", "will sponsor"); anything hedged or redirected ("pending", "maybe", "if", "declined", "try another", a "?") does not count | `status <slug> ready` |
| KILL | window passed, no sponsor (exit code 1) | `status <slug> parked` |

Useful flags: `d:clock --now 2026-10-20` (what-if dates), `d:clock --json` (one JSON document,
`next` included), `d:export --cites` (keep `[F-###]` tags; they are stripped by default because
forum readers can't use them), `d:post --dry-run`, `d:log --date YYYY-MM-DD` (backfill).

Dates are strict `YYYY-MM-DD` and must exist (`2026-09-31` is refused). `d:post` refuses future
dates, and re-running it (for example to add `--url` later) keeps the original `posted` date, so
the kill clock can't be reset by accident. Only an explicit `--date` moves it, and it says so.
All `d:` commands refuse an application whose call.md is not `track: D`.

`budget_unit` decides which currency leads: `ETH` gives "11.5 ETH (about $28,750)", `USD` gives
"$37,000 (about 14.8 ETH)". USDC rows count as USD. `eth_usd` accepts `2500`, `"2,500"` or `"$2500"`;
anything else fails `D:budget`. Amounts use a dot for decimals (`1.5`, `12,000.50`).
`kill_after_days` must be a positive whole number; a typo fails `D:kill-window` and blocks `d:post`.

## Checks added to `fund check`

- `D:criteria-quotes`: the template's example criteria ("replace with the DAO's own wording") are
  still in call.md. Warns, and fails from `in-review` on.
- `D:budget`: budget.md parses; the total (converted with `eth_usd` when rows mix ETH and USD) sits
  inside `min_budget`..`max_budget` in `budget_unit`. An empty budget warns, and fails from
  `in-review` on.
- `D:kill-window`: fails when `posted` + `kill_after_days` has passed with no sponsor and the
  status isn't closed. Prints the `status <slug> parked` command.
- `D:sponsors-pii`: fails if sponsors.md contains an email address or phone number (reported
  masked). `d:log` refuses such input before it writes anything.
- `D:proposal`: `status: ready` needs proposal.md. It warns when proposal.md differs from what
  `d:export` would write now (and fails at `ready`). It compares content, not file times, so
  `fund status` edits don't count; `d:post` and a new sponsor row do, because they change the
  closing line.
- `D:kill-window` also fails on a malformed `posted` date and warns on a future one.

## Add a new DAO in under 5 minutes

1. `node bin/fund.mjs new <dao>-dao --track D --program "<DAO> proposal" --url <guidance-url>`.
2. In `call.md`, set `dao: <Name>` (used in the sponsor ask), `proposal_title`, `eth_usd` (today's
   rate), `min_budget` / `max_budget` (the DAO's range, or your own cap), and `kill_after_days` if
   the DAO's candidate or sponsorship period differs from 21 days.
3. Replace the five template criteria rows with the DAO's own guidance, quoted verbatim (or paste
   the guidance into source.md and run `prompt extract <slug> --run --out applications/<slug>/call.md`).
   `D:criteria-quotes` warns until you do.
4. Copy the budget rows and draft sections from `applications/nouns-dao/` if the pitch is the same.
   Rewrite "Why this DAO" for the new DAO.
5. `node bin/fund.mjs check <slug>`, then `d:export <slug>`.

A DAO without a sponsor step (a grants committee or domain allocator, as on Arbitrum's Questbook)
still fits: log the reviewer's role in `d:log`, and set `kill_after_days` to how long you will wait
for an answer.

Rules that still apply: numbers in draft.md cite facts/FACTS.md; no BGA, Mantle, Stellar Community
Fund, Giveth, investment or credit programs; no token-sale language (see facts/frames.json).
