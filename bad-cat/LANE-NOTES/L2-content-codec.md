# L2 Content + codec: notes for LEAD and other lanes

No `types.ts` change is required. These are deviations from or clarifications of the spec.

1. **The cat code is 18 characters, not 15.** It uses the 88-bit GDD layout (11 bytes) plus a CRC-16 (2 bytes),
   which makes 13 bytes and 18 base64url characters. "15 chars" was the length without the CRC. The comment on
   `CodecApi.encodeCat` in `types.ts` still says 15; `CAT_CODE_LENGTH` is exported.
2. **The ghost count is variable-length.** Each run is `dir:4 speed:2 buttons:4` plus a count in 3-bit groups
   with a continuation bit, instead of `count:8`, so runs never need splitting. The header is
   `version:4 flags:4 | roomKey:32 simVersion:8 ticks:12`, then the CRC-16. `roomKey` = FNV-1a of the room id
   (`daily-018`, `glass`, `ugc-…`).
   - On recorded-like 75 s runs a ghost is about 290–335 characters.
   - Deflate does not shrink the bit-packed data, so `encodeGhost` usually writes the uncompressed form. The
     flag bit and the async decode for deflated payloads are in place.
3. **parseLink (M0)** leaves `ghosts: []`, as LANES.md says. It does decode `rp` (the clip handoff replay)
   synchronously when the payload is uncompressed, which is what `buildLink` writes.
   - `parseLinkFull(url)` is async and decodes `g`, `g2` and a deflated `rp`. Use it from M1a.
   - `buildLinkAsync` writes deflated ghosts.
4. **Cat card name:** `LinkState` has no field for `/c/<cat>?n=`. `parseLink` returns `LinkStateX`
   (`LinkState & { catName?: string }`), and `buildLink` accepts it.
5. **Room links (`/r`, M2 format, already implemented):** `n=` is the room title and `a=` the author, as in the
   GDD. Ghosts in a room link carry `c` but no name (the GDD reuses `n`; M2 should choose a parameter).
   - The room payload adds `size:2` (12×10 / 14×12, which also gives the run length) and the ancestors.
     Decoded rooms get `id = ugc-<crc32>` and `seed = crc32`.
6. **Standalone hash links:** `base#d=18&…`. `buildLink` switches to the hash form when `base` contains `#`.
   Also accepted: `#glass`, `#pick`, `cat=<code>`, `r=<room>`.
7. **Preview days:** `dayNoFor` gives ≤ 0 before 2026-11-16. `dailyRoom(n ≤ 0)` returns a preview room
   (`preview-001` for day 0, title "Kitchen Preview: Breakfast Heist"), so pre-launch testing gets one room
   per local day and the one-ranked-run-per-day rule still works.
   - `dayLabel(n)` gives "Kitchen #18", or "Kitchen Preview 2026-11-15" before launch. Use it for captions
     and URL lines.
   - Links accept negative day numbers (`/d/-5`).
8. **Routines:** `ROUTINES` holds 4 Chef Dad tempos (indices 0–3), because `routine` is 2 bits in the room codec.
   The variants pick one each.
   - `resolve(room, 'ftue')` returns a routine copy with `eventTick = 450`.
   - The first turn at tick 240 and `FTUE_TICKS` are still L1's job. `FTUE_FIRST_TURN_TICK` is exported for
     reference.
   - `resolve` falls back to shell 0 / routine 0 for unknown indices, so a crafted link never throws.
9. **Rooms are baked JSON** (`src/content/rooms/*.json`), generated by `src/content/authoring.ts`.
   - `rooms.bake.test.ts` fails if the JSON and the generator drift apart.
   - To re-bake: `BADCAT_WRITE_ROOMS=1 npx vitest run src/content/rooms.bake.test.ts`. This also writes
     `public/daily/index.json` (days 1–21; static, not fetched by the game in M0).
10. **Kitchen inert props:** the roomba (kind 20) is placed at (11,9) in every room. The tablecloth (kind 14) is
    not placed, because it would take up a whole table cell.
11. **Validator (`validate`) is conservative.**
    - It uses Dijkstra over the heightmap. Trot steps cost 7/10 ticks, jumps are orthogonal only and cost 12,
      and blocking props and the human are walls.
    - A target is wreckable only by an orthogonal push off an edge from a reachable cell at the same level.
    - `travelTicks` and `wreckTicks` are exported for `tools/validate.mjs` (L8).
