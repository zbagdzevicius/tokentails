Why each Motored label has 3 gift pools, all filled from one address

  1. Each label is a gift pool, not a person. A pool is one on-chain address that Token Tails created for the event (keys held by Token Tails) to hold gift money and send it to the shelter. Pools are not Motored customers.
  2. The event ran 3 times (Oct 16–22, Oct 25–31, Nov 6–12). Each round opened 480 new gift pools and reused the labels user-1 … user-480, so every label maps to exactly 3 pools (480 labels × 3 pools): 3 rounds, not 3 people.
  3. One funder. A single Motored event funder filled each pool with its gifts plus gas, in 1,440 funding transfers and nothing else. Only the Token Tails team wallet ever topped up that funder (3 top-ups, 154 USDC). Each round ran for a week on a real-world hourly activity curve: a full event-scale load test, with every gift settling on Arc mainnet.
  4. How we count it: one related-party sponsor. 1,440 gift pools, not 1,440 donors, and not outside traction.

built and tested · next Motored event

Motored × Stripe: the template for sponsors in our queue

The Motored pilot showed the rail at event scale. The next step connects a sponsor's own checkout directly: Motored's Stripe account tells our backend about every paid order, and the backend turns each order into one gift on Arc. Every sponsor in our queue gets the same integration.

1 · A real order is paidMotored's Stripe sends checkout.session.completed to our backend, signed with the webhook secret.
2 · One gift per orderEach paying customer gets one gift pool; each paid order adds exactly one gift. A resent webhook cannot pay twice. A refund or dispute before the gift is sent cancels it; a gift already on Arc stays with the shelter.
3 · Settled on ArcThe pool calls ShelterSplit donate(), which pays 100% to Pink Paw's wallet. No customer name, email or id is stored, only salted hashes.

Source: backend/src/shelter/motored/ (webhook, gift sender and retry keeper, with tests).

How it works · and why it works anywhere

A rail anyone can call. No Token Tails server in the money path.

The rail is not a Token Tails feature. It is permissionless contracts. Any app on any EVM chain can call donate(memo) or disburse(amount, memo) without an API key. The split pays the shelter in the same transaction and keeps no balance.

The chain enforces

  • Deployed bytecode equals the public MIT source (Sourcify exact match on all 4 Arc mainnet contracts).
  • Who gets paid: preview() returns Pink Paw's wallet at 10,000 bps.
  • Every payout emits a public event with its memo.
  • DonateRouter has no owner, admin or sweep. It reverts if any wei would reach the treasury or the payout list changed after signing.
  • The old Token Tails-held payee wallet was swept to Pink Paw's wallet.
