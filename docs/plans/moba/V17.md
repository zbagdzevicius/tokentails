**Status:** implemented on `feat/pawlegends-v17` (not pushed). Every gate passes, with balance judged on the two pooled windows as §5.1 says; a single 2,000-seed window can still show one or two heroes about 0.5 pp outside 46–54% (§6.5). Results and deviations are in §6.

**Sources:**
- The champion interaction review (`CHAMPS.md`, sim v15 numbers, re-checked against v16 data below). Gaps 1 to 10 and proposals P1 to P10 there.
- Feel research `RESEARCH.md` §C6, the counter-play rules:
  - hard-CC skill shots: windup ≥ 300 ms (9 ticks), ≥ 400 ms (12 ticks) when range ≥ 9 m, travel ≥ 350 ms at max range;
  - after 2 s of hard CC within 4 s, 1 s of CC immunity;
  - one hero's full combo ≤ 70% of an equal-level squishy's max HP;

  - every area CC has a telegraph.

Units: 30 ticks = 1 s, so 1 tick ≈ 33 ms. Distances in mm. "Reaction budget" is 250 ms offline and about 400 ms online (CHAMPS.md). Sideways move speed is 5 m/s at level 10.

## 3. Counter-play batch, ordered by impact

Each item is one commit with its tests, the goldens and the balance baselines. "Gap" refers to CHAMPS.md §3.

### 3.1 Steadfast: CC diminishing returns and immunity (gap 2; rule "2 s in 4 s → 1 s immunity")

**Why first:** chains reach 2.5 s (measured) to 3.25 s (two 3-hero comps), longer than the ~2.1 s Nine Lives time to kill. No other item fixes this, and items 3.2 to 3.6 are tuned against a capped chain.

**Data** (`data/effects.ts`):
```ts
/** Sim v17 Steadfast: hard CC on a hero counts toward `cap` ticks inside a `window`-tick window; reaching it grants `immune` ticks of CC immunity after the lock ends. */
export const CC_DR = Object.freeze({ window: 120, cap: 60, immune: 30 });
```

**World** (`sim/world.ts`): two new per-entity `Int32Array` fields.
- `ccWinT`: ticks left in the current window (0 = no window).
- `ccSum`: hard-CC ticks counted in the window.
- Both are allocated with the others, **added to the hash list** next to `ccImmT` (`world.ts:630`), and reset in `clearStatus` (death, respawn). They are not in the render snapshot; render reads a Buff bit (below).
- `Buff.Steadfast = 1 << 19` (`// lint-sim: allow (a bit index)`), set in `map/brush.ts` buff flags when `ccImmT > 0 && ccSum >= CC_DR.cap`.

**Rule** (`effects/status.ts`, a new `drGrant(w, id, ticks): number`, heroes only):
```ts
/** Ticks of lock `id` is already under: the longest of stun, fear/charm, root and a knockback in flight. */
const lockLeft = (w, id) => Math.max(w.stunT[id], w.fearT[id], w.rootT[id], w.fmKind[id] === FM.Knock ? w.fmT[id] : 0);

export function drGrant(w: World, id: number, ticks: number): number {
  if (id < RANGE.heroes || id >= RANGE.minions) return ticks; // minions, camps: unchanged
  if (w.ccWinT[id] === 0) { w.ccWinT[id] = CC_DR.window; w.ccSum[id] = 0; }
  const cur = lockLeft(w, id);
  const add = ticks - cur;            // lock this CC adds beyond what is already running
  if (add <= 0) return ticks;         // fully overlapped: free, counts nothing
  const grant = Math.min(add, CC_DR.cap - w.ccSum[id]);
  w.ccSum[id] += grant;
  if (w.ccSum[id] >= CC_DR.cap) w.ccImmT[id] = Math.max(w.ccImmT[id], cur + grant + CC_DR.immune);
  return cur + grant;
}
```
- Called after the `ccImmune` check in `stun`, `root`, `fear`, `charm` (they store the returned value instead of `ticks`), and in `knockback` with `EFFECTS.knockbackTicks` (the push distance is never shortened; only the count matters).
- Counted: stun (including Snub, Avietė's stun and Bengas W), fear (Hiss, Lure, Talk Back), charm, root (Lambo R, Sage trap, Domino R, Marshmallow freeze), knockback and pull.
- Not counted: slows, the Brutus tether (handled in §3.5), self-roots (Pixel E, Nugget E, Guard Post), Rocket's nap.
- `tickStatus` decrements `ccWinT`. The window opens at the first counted CC and is not refreshed by later CC, so the rule is exactly "60 ticks of lock inside 120 ticks".
- `cleanse` (Purr-ify, Meatball R, Pixel R, Chili R) does **not** reset `ccSum`.
- When the cap is reached, `ccImmT` covers the rest of the current lock plus 30 ticks. Further CC in that time is refused by the existing `ccImmune`.

**Determinism and replay safety:**
- Integer only; no RNG; no new iteration order. Within one tick the CCs resolve in the existing cast and projectile order, so which CC gets truncated is fixed by that order.
- Two CCs that hit one hero in the same tick always come from the same enemy team, so the truncation order cannot favour a map side.
- New hashed fields: v16 replays re-sim on the frozen v16 bundle, so they are unaffected. The v17 golden hash changes once, here.

**Effect on the known chains** (re-measured with the chain probe turned into a test):

| Chain | v16 lock | v17 lock |
|---|---|---|
| Lambo E 15 → Lambo R root 30 → Gabė R charm 30 (measured 2.5 s) | 75 ticks | 15 + 30 + 15 = **60**, then 1 s immune |
| Cats 3v3: + Duchess Snub 23 | 98 | **60**; the Snub misses |
| Dogs 3v3: Frankie W 15 → Bravo R 30 → Howler R 6 + 23 → Frankie R 23 | 97 | 15 + 30 + 6 + 9 = **60**; Frankie R misses |
| Meatball W 23 → Q knock 6 → E knock 6 + Hiss 30 | 65 | **60** |

**Tests** (`tests/unit/steadfast.test.ts`, new):
1. Stun 30, fear 30, charm 30 back to back on a level-10 hero: exactly 60 disabled ticks; `ccImmT` is 30 when the lock ends; a stun 10 ticks later misses; a stun 31 ticks later lands.
2. Stun 30 applied while 20 ticks of stun remain: `ccSum` grows by 10.
3. Stun 15, wait 121 ticks, stun 60: the second stun lasts 60 (a fresh window), then immunity.
4. A minion and a camp rat stunned for 200 ticks stay stunned 200 (heroes only).
5. Purr-ify inside a window keeps `ccSum`; death clears `ccSum`, `ccWinT` and `ccImmT`.
6. `hash.test.ts`: changing `ccSum` or `ccWinT` of one hero changes `hashWorld`.
7. The chain probe from `CHAMPS.md` §2(d) (Lambo E → R → Gabė R, victim walking away) as a test: the longest run of disabled-or-rooted ticks is ≤ 60.
8. `Buff.Steadfast` is set only while the DR immunity runs, not for a plain Purr-ify.

### 3.5 Brutus cage exit (gap 5)

| Change | v16 | v17 |
|---|---|---|
| `brutus.r.duration` | 90 | **75** |
| Talent Arena of Honour `r.duration` | 120 | **105** |
| Pounce cast by a tethered unit | blink clamped inside the ring | **`breakTether(w, id)` first, then the blink resolves unclamped** |

- New helper in `effects/tether.ts`:
  ```ts
  /** Sim v17: the tethered foe breaks out (Pounce, any cleanse). The arena ends for both; the owner keeps nothing. */
  export function breakTether(w: World, id: number): void {
    const z = w.tether[id];
    if (z >= 0 && w.zAlive[z] !== 0 && w.zOwner[z] !== id) endArena(w, z);
  }
  ```
  `castTrick` calls it before `blink` for Pounce; `cleanse` calls it first. Brutus casting his own Purr-ify keeps his arena (the `zOwner` check).
- Ending the arena also ends Brutus's 30% reduction, since it reads `w.tether[id]` (`heroes/brutus.ts:140`).

**Tests:**

### 3.11 Burst cap: measure, then tune per hero (rule "combo ≤ 70%")

**Approach:** no new system. Nine Lives (per victim, 45% per rolling 1 s on Hard and PvP) is already the structural cap; a fixed check proves the 70% rule holds, and a hero that breaks it is tuned in its own data.

- **`tests/unit/burst-cap.test.ts` (new):** for each of the 20 heroes at level 10, no Toys, `PVP_RULES`, against a level-10 target of the squishiest marksman or mage (lowest level-10 max HP, picked by the test from the data), standing still:
  - script the full combo (every ability and basics, each cast the tick it is ready, the `burst.probe.ts` script from the review);
  - measure HP lost in the first **45 ticks** (1.5 s) after the first hit;
  - assert ≤ **7000 bp** of max HP. Also log the 60-tick loss for the record.
- The review measured up to 48% in 1 s and 74% in 2 s (Clem on Rocket). Expect 1 to 3 heroes over 70% at 1.5 s.
- **Fix for a hero over the cap:** lower its largest burst ability's `dmg` and `dmgPerLevel` by the overshoot share (for example 74% → 70% is −5.4%), never its `pvp` row and never Nine Lives. Re-run.
- Report the table (hero, 45-tick loss, 60-tick loss, fix) in §6 of this file.

### 6.1 Deviations from the plan

- **Freeze and bump in one commit.** `vendor-sim` refuses a `FROZEN` entry that is not older than `SIM_VERSION`, so step 1 and step 2 share commit `5401a712`, as v15 → v16 did.
- **Steadfast window.** The window does not close while a lock is still running. Without this rule, a chain that straddles the 120-tick edge reached 85 continuous ticks. When the cap's immunity ends, the window closes at once, so the next CC opens a fresh one. This is also needed for the plan's own test: a stun 31 ticks after the immunity lands.
- **Self-roots.** Pixel E, Nugget's Sploot and Meatball's Loaf now call a new `selfRoot`, which skips Steadfast. `root` counts.
- **Brutus R cut.** The 30% cut read `kRT`/`kFoe`, not `tether`. v17 clears both when the arena breaks, and `incoming` also checks `tether`.
- **Pack Hunt victim reach.** The fizzle range is `r.range + r.slip (2000)` plus the victim's body radius.
- **Domino R test.** It uses 10.3 m, not 10 m: the 9.5 m reach adds the victim's body radius.
- **Frankie R windup 12** landed with the telegraph commit, because `reaction.test.ts` needs it.

- **Talk Back.** `deterBasics` takes the attacker, so ranged bots beyond 4.5 m keep shooting.
