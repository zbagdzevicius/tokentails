| Variable | Default | Effect |

## Decisions applied (plan recommendations)

- **#26 paw economics:** daily settlement, budget sized to DAU and revisited monthly. Every settlement
  stores `suggestedBudgetWei` = ceil(30-day average paws per day) × `PAWS_AMOUNT`; the ADMIN
  settlements route shows it next to `budgetWei`. Pro rata, so nobody is told "budget used up".
- **#27 purchase share:** modest bps from a future date, nothing for earlier orders. Implemented as a
  read of `purchase_share` (C-002) from the facts registry only. Recommended values to enter there:
  **5 % (`value: "5"`) from `effectiveAt: 2026-11-01`** (request 1). Until then `pledges.status` is
  `not-started` with no rows.
- **#28:** accept amber. Confirmed payouts are SHELTER-CONFIRMED (amber); signatures are refused with
  `PAYOUT_HANDOVER_PENDING` until `handoverStatus: handed-over` with a `publicWallet`.
- **#31:** eligibility friction accepted as in F7.5 (verified email, 24 h at settlement, promoted
  guests' age counts from `promotedAt`).
- **#78:** second reviewer before publish: approver is neither author nor redactor; enforced in the
  service, the schema hook and the CMS.
- **Paws and Heist rows:** Catnip Heist saves do not count towards the two runs, consistent with the
  instant-treat rule from gate-w3 (not played with the cat). Deleted and merged accounts get no paw.
- **Receipts are hashed, never stored** (they can hold names and bank details). Payout `reference`
  and FX source refuse emails, phone-like runs of 9+ digits and IBANs.
- **Outcome redaction is always required**, also without a photo (the reviewer attests the text).
- `#97` stays deferred: no ShelterSplit deploy, no send.

## Client verifier (for the client owner)

`verifyMerkleProof` in `client/components/claims/merkle.ts` already walks the tree correctly. Plug in:

```ts
import { keccak_256 } from "@noble/hashes/sha3"; // or any keccak-256
const hashPair = (a: string, b: string) => {
  const [x, y] = a <= b ? [a, b] : [b, a];            // already sorted by verifyMerkleProof
  const bytes = (h: string) => Uint8Array.from(h.slice(2).match(/../g)!.map(n => parseInt(n, 16)));
  const out = keccak_256(new Uint8Array([...bytes(x), ...bytes(y)]));
  return "0x" + Array.from(out, v => v.toString(16).padStart(2, "0")).join("");
};
// leaf = keccak256(utf8(`${pawId}|${userHash}|${day}`)); proof from GET /impact/me paws.proof
```

`merkle.spec.ts` and `paws.service.spec.ts` import the client file and verify server proofs with the
backend's `hashPair`, so the shapes cannot drift.

## Review fixes (second pass)

All 13 review findings were checked against the code and are valid; all are fixed except #7, which
is a request to another owner (see Requests, item 6).

1. **Edit-then-confirm by a second manager.** `ImpactPayout.editors` (`$addToSet` in `updateDraft`);
   `confirm` refuses the creator and every editor (`PAYOUT_AUTHOR_CANNOT_CONFIRM`), re-checked in the
   atomic update filter; the view adds `editedByMe` and `canConfirm` excludes editors. CMS copy updated.
2. **Unpublish left the image public.** `approve` stores `image.key`; `unpublish` deletes the Spaces
   object (`defaultOutcomeDeleter`, `DeleteObjectCommand` with the `aws.utils.ts` credentials, kept in
   `impact/` because `shared/utils` is not mine) and resets the outcome to "awaiting redaction" (new
   redaction mark and second reviewer needed). A failed delete is logged and recorded in
   `unpurgedImageKeys` for a manual purge. `ImpactAdminController.unpublishOutcome` then calls
   `ImpactService.withdrawOutcome`, which strips the outcome from every stored snapshot, re-mirrors
   the latest to the CDN and drops the cache. A failed `approve` write deletes the copy it uploaded.
3. **setImage/approve race.** `approve` hashes the bytes it is about to upload against `image.sha256`
   and puts `image.sha256` in the publish filter. `setImage` and `setRedacted` return 409, not a 500,
   when the outcome was published under them.
4. **Payouts confirmed by staff.** `ShelterMembersService` refuses MANAGER and above as members, and
   `confirm` refuses staff (`PAYOUT_STAFF_CANNOT_CONFIRM`) in case a member is promoted later. No
   override flag: SHELTER-CONFIRMED has to mean the shelter.
5. **A missed 00:30 run.** `catchUp` settles any of the last 3 days without a settlement row; it runs
   after the nightly settlement and once an hour from the reconcile cron, and leaves yesterday to the
   nightly run for one hour after 00:30.
6. **Late settlement and the 24 h rule.** `settlementAt = min(now, settlementTimeFor(day))`.
8. **Fake attestation lines.** `reference` and `fxSource` refuse control characters (DTO `@Matches`
   and again in `writeOf`).
9. **Salt.** Returned to the owner as `paws.proof.salt` (the design the comments described); the
   privacy spec checks another paw's salt never appears.
10. **`transient`** added to the settlement's user projection.
11. **Confirm and file type.** Confirm checks size and hash only.
12. **`published` count** uses `publishBlocker` over every published row, not `countDocuments`.
13. **Redaction a11y.** Keyboard alternative: left/top/width/height percent inputs and "Add box".

## Known limitations

- A settlement whose send was off stays `built`; enabling the send later does not pay old days (only
  an ADMIN `POST /impact/paws/:day/settle` does, one day at a time).
- Proofs are rebuilt from the stored leaves per day (cached for 3 days per instance); a day with
  very many paws costs one query of leaves on the first proof request.
- Membership does not stop an author with two accounts; admins review who they grant.
- CMS draft edit cannot clear an optional field to empty (blank fields are not sent).
- Signatures are pasted; the CMS has no wallet connection.
- `GET /impact/outcomes` lists at most 100 outcomes (`published` counts all of them).
- An unpublished image can stay in CDN edge caches until they expire; purge the key by hand if needed.
- Other replicas serve the old snapshot for up to their one-minute `GET /impact` cache after a withdraw.
- The catch-up looks back 3 days; an outage longer than that needs an ADMIN `POST /impact/paws/:day/settle`.
