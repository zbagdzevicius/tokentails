### 3. `fund facts` (`funding/framework/bin/fund.mjs` + `lib/facts/`)

- `fund facts build [--check] [--quiet]` generates six files:
  - `FACTS.md`, in the same table format. `company-reported` rows appear as `unverified`, so
    `verify.mjs` and `fund check` keep their four statuses.
  - `client/public/facts/facts.json`: the public subset. It carries no internal claim text, notes or
    repo-path sources; only URLs leave the repo.
  - `client/lib/facts.generated.ts`, `backend/src/impact/facts.generated.ts` and
    `catnip-heist/src/facts.generated.ts`: the `FactId` union, the `FACTS` record and
    `PUBLIC_FACTS_PATH`. They have no imports and no `satisfies` (TS 4.8 safe). The backend copy
    carries `/* eslint-disable */` so prettier doesn't reformat it.
  - `campaign.json`.

  The output is deterministic, with no timestamps. Writes are atomic.
- **Schema rules:**
  - Unverified and retired entries never have surfaces.
  - A surfaced entry needs display text and a `maxAgeDays`; only SEI history is exempt.
  - `sei-era` entries need chain `sei`, the past tense and SEI in the display.
  - A `company-reported` display must say so.
  - Only `L-` entries are live.
  - A future-tense display must not say money moved.
  - Goal and campaign shape is checked, and only one campaign is allowed.
  - The build rejects email, phone and IBAN patterns anywhere in the registry.
- `fund facts absorb [--dry]`: `fund refresh --write` still edits FACTS.md rows. This moves Value,
  Date and Status edits back into facts.json. A changed Fact or Source cell is reported for a person
  to copy by hand.
- `fund facts report [--offline] [--out FILE] [--json]`: the weekly checks. It covers:
  - staleness;
  - goals that are not started, running or ended;
  - evidence that is ready;
  - the `sources.json` probes, run through `refreshFacts` and never writing;
  - the impact snapshot, when `FACTS_IMPACT_URL` is set. It flags a missing path, an old `asOf` and
    `sources.chain = 'error'`.
- `fund facts gate`: the release gate. It runs `build --check` and fails if any surfaced fact is
  stale. It needs no network.
- Plain `fund facts` still validates FACTS.md as before.

### 4. Copy lint: `tools/copy-lint/` (own `package.json`, `typescript` 5.8.3 pinned)

- **Extraction** uses the TypeScript AST. It reads string literals, template spans, flattened JSX
  text (inline tags joined into one sentence), text-bearing attributes, object literals' text
  properties (checked one by one and as a joined object) and JSON prose. It skips imports, keys,
  comparisons, class-name helpers, analytics calls and asset loaders.
- `isApp ? app : web`, `!isApp && …` and `if (isApp)` branches mark text as web-only or app-only. A
  file can opt out of the app rules with `// copy-lint: web-only <reason>`.
- **Rules R1-R12** are written in `docs/CLAIMS.md`:
  - The G5 tone regex (R9) applies outside `components/legacy/**` and the Vault. It ignores the brand
    and auth tokens ("App Check token").
  - The backend rule set reads only `message`, `label`, `name`, `description` and `revealTitle`
    values, exception messages and HTML templates.
  - App-build rules (R10) ban USDC, `0x` hashes, explorers, wallets, chain names and ON-CHAIN.
  - `/Tails per/i` and any Tails-to-money rate are banned everywhere (R8), legacy files included.
  - Other rules: claims need an id within 3 lines or `// claim:fiction <reason>`; Token Tails must be
    the subject of money verbs; no giver counts; goals must cite their C- entry; SEI history must say
    SEI; company-reported and date labels must travel with the number; cited ids must exist, be
    public and list the file's surface.

## Known limitations

- The lint is heuristic. The real-world noun and impact verb lists will produce false positives and
  miss rephrased claims. `// copy-lint-ignore R## <reason>` and `// claim:fiction <reason>` are the
  escape hatches, and both require a reason.
- The static scan cannot see copy the backend sends at runtime or text managers type into the CMS.
  The F11 runtime Playwright copy scan is not built.
- R5 infers a file's surface from its path (landing, heist, shelter-payouts, impact, game). A shared
  component used on several surfaces is checked against one.
- Money-verb subject detection (R3) finds the subject only among the words before the verb in the
  same sentence (the real-world noun may be anywhere in the copy since the review fix). "You pay a
  small gas fee" in `WalletDonate.tsx:53` is a real user payment and still gets R3; its owner decides
  whether to rephrase or add `copy-lint-ignore R3 <reason>`.
- R1 unit matching uses small synonym groups (players/users/members/people;
  cats/strays/animals/rescues; countries). A number whose noun is outside them needs an entry with
  that exact unit.
- C-001's `shareBps` (10000) is an assumption. The ShelterSplit recipient config is not in the repo,
  so CI cannot read the real share.
- The `L-` value paths (`shelters.countries`, `money`, `heists.verified`) follow plan F7.3. If the
  impact module names them differently, update `live.path` in facts.json; the weekly report flags a
  missing path.
- Goal reachability uses the code default cap. A production override through `SHELTER_DONATE_DAILY_BUDGET_WEI`
  is invisible to CI; the live copy should read `dailyBudgetWei` from
  `/shelter/donate/status`.

## Review fixes (second pass)

The review listed 8 issues. I checked each one and all 8 were valid; each is fixed and has a test.
One suggested fix was wrong as written and was changed (issue 1).

1. **`fund facts build` overwrote FACTS.md edits.** The suggested fix ("refuse when `absorb --dry`
   would patch rows") would also refuse the normal flow: edit facts.json, then build. In that case
   FACTS.md is only behind, and absorb would copy the old values back over the new ones.
   - Instead, FACTS.md now ends with `<!-- fund facts build: rows sha256:… -->`, a hash of the rows
     it was generated with. `factsMdState()` returns `current`, `behind` (untouched since the last
     build, so safe to overwrite) or `edited` (rows changed since the last build, or a file from
     before the stamp whose rows differ).
   - On `edited`, `fund facts build` refuses and points at `fund facts absorb`. The new
     `--discard-md` flag overwrites anyway. `--check` names absorb only when FACTS.md was really
     edited.
   - `readFactRows`, `verify.mjs` and `fund refresh --write` ignore the comment line.
   - Tests: the reviewer's F-011 190,000 case (refused, the edit kept, absorb then build keeps
     190,000), `--discard-md`, the `behind` case, a file from before the stamp, and the three states.
2. **`claim:fiction` and unrelated ids cleared R1.** The fiction marker now clears R2 only. R1 needs
   a cited `F-`, `L-` or `C-` entry whose `unit` counts the matched noun (`unitMatches`, with small
   synonym groups). `// claim:fiction game` next to "800+ strays saved" is R1, and so is F-011 next
   to it ("counts strays, but the cited F-011 (followers)…"). A `P-` id never covers a count.
3. **The plan's Heist rail copy failed the lint.**
   - C-004 and C-005 are now `tense: "present"`: they are config amounts. The new live entry
     `L-rail` (`GET /shelter/donate/status` → `railState`: not-deployed, paused, live, exhausted;
     surfaces heist and shelter-payouts) carries whether the rail is live.
   - The Heist ships in the app export (`client/scripts/check-app-export.mjs` requires
     `heist-game/index.html`), so it stays an app target. The extractor now treats `isWebHost`,
     `isWeb`, `IS_WEB`, `isWebBuild` and `HEIST_WEB` as web flags, and `isAppHost`, `inApp` and
     `HEIST_APP` as app flags. Task 3e provides one at runtime.
   - The line `isWebHost ? '…treat on Arc' : '…treat'`, cited to `C-004, L-rail`, has zero findings.
     Without the branch it gets only R10.
   - Schema rule: an entry on an app surface (`game`, `heist`, `store`) must have a display that
     passes the R10 word list, or an `appDisplay` that does. C-004 is "a $0.01 treat" and C-005 is
     "$1 of treats a day". `appDisplay` is in the public subset and in the generated `PublicFact`
     type (`string | null`).
   - The word list is kept in both `schema.mjs` and `rules.mjs`. A test fails when they differ.
   - `registry.test.mjs` now runs R10 on the app surfaces, checking `appDisplay` in the app branch.
4. **Short strings skipped.** A copy-position string with a space that doesn't read as prose is now
   a `short` unit. It gets R8, R9 and R10, but not the claim rules. One-word strings stay out,
   because they are keys, symbols and class names. The same applies to JSON values. R8 gained the
   currency-word form, so "1 USDC = 100 Tails" is R8 + R10 and "100 Tails = $1" is R8.
5. **Goal reachability assumed a 100% share.** `goal.shareBps` (default 10000, now explicit on C-001)
   scales the cap: `cap x shareBps / 10000 x days`. The schema requires an integer from 1 to 10000.
   The build warns when a goal has no headroom (`spareDays` 0): **C-001 at 90/90 has zero headroom,
   so any day under the 1 USDC cap means the goal is missed.** A 50% share makes 90/90 unreachable
   (at most 45 USDC, needs 180 days), and `--check` fails.
6. **Heist level copy was not scanned.** There is a new `heist-levels` target:
   `catnip-heist/src/levels/*.json`, excluding `*.solution.json`, reading only `meta.title`,
   `meta.objectives[]` and `meta.hints[].text` (the `jsonPaths` option on `extractJson`). All 8 level
   files are scanned and have 0 findings: "Open the vault and free the shelter cat" has no impact
   verb.
7. **R3 missed subjects before a colon.** Whether the copy is about the real world is now read from
   the whole unit. "Shelter treats: every heist funds them." and the live `ui.ts:735` both get R3.
8. **Personal-data patterns were narrow.** Added local phone formats ("(415) 555-0100",
   "415.555.0100", Lithuanian "8 600 12345" / "860012345"). IBANs are now matched in any case once
   spaces are removed, when they pass the ISO 13616 mod-97 check; the uppercase pattern is unchanged.
   Negative tests cover dates, tweet ids, wei constants, thousands separators and a mod-97 failure.
   The real registry still has no hits.
