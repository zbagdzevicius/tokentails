## Decisions applied (plan recommendations)

- #19: roster SCOUT, PINKIE, SHADOW, MISTY, SUNNY; the commit uses `STARTER_ART` (2a) for the look.
- #20: legacy Cleocatra owners get a one-time rename offer (`Cat.renameOffer`), skipping the 30-day
  window once. Not offered when the cat is minted, or the account is deleted or a guest.
- #21: pack pool exhaustion refunds the order.
- #22: one free rename per 30 days, frozen after mint. A moderator reset or rename restarts the
  window (`nameChangedAt: now`), so a reset player cannot pick another offensive name at once.
- #23: Latin only (Latin-1, Extended-A/B, Extended Additional; Lithuanian works).
- #25: follow notifications later by email or push; nothing was built for them, never Telegram.

## Deviations and choices

- Featured and follow use `rescueBlessingFilter()` (`kind: 'rescue'`, or an un-backfilled row outside
  the portrait shelter) rather than a bare `kind: 'rescue'`, so the endpoint is not empty before
  `backfill-blessing-kind.js` runs. Portraits are excluded either way (spec).
- Featured cats rotate every 10 minutes but deterministically (see the review fixes below), so
  different shelter cats get seen and every instance agrees.
- `spent` keeps its USD meaning and is still written next to `spentUsd` at the verified sites, so the
  existing boards keep working. The legacy inflation already in `spent` is not recomputed; the plan's
  `spentUsd` is the clean figure.
- Empty pool on a Stellar payment cannot be refunded by the backend (it holds no treasury key), so the
  order is `FAILED_GRANT` with `refund.state: 'due'`. Stripe refunds run automatically.
- Name reports are limited to starters (the only player-named cats) and to registered players
  (guests are not on the allow-list for reporting).
- `PUT /cat/:id/name` refuses an uncommitted starter (409): the first name is set by `POST /user/starter`.
- `GET /cat/adopt/:_id` now refuses to copy a starter. Previously any cat id, including another
  player's starter, could be cloned.

## Review fixes (2026-10-01)

Nine review findings, all verified and fixed:

1. Reserved featured names were random, per instance, and grew with `?limit=`. `FeaturedBlessingService`
   now ranks the pool by `sha1(_id + floor(now / 10 min))` (no `$sample`), caches one ranking per
   bucket, and `featured(limit)` is the first `limit` of it, so every instance and every limit agrees.
   `reservedNames()` is only the default 3 of the current and previous bucket (at most 6 names); a
   `limit=12` call changes nothing (spec).
2. Latin letters with no a-z skeleton (`ƒ`, `ŧ`, `ƀ`, `ǀ`, `ƚ`, ...) vanished from the folded name, so
   `ƒuck` passed. Any allowed letter that folds to nothing is now NAME_CHARS. Latin Extended-B stays
   allowed for letters that decompose (Romanian `Ștefan`, Vietnamese `Phương` accepted, as vectors).
3. Compound words added anywhere: dickhead, cocksuck, shitface, cumshot, jackass, dumbass, sexcat,
   fukyou (`shit` stays whole-word, so Shiitake passes).
4. Featured real cats are screened with the exported `isBlockedCatName`; `viagra` is blocked. The live
   Pink Paw record named `VIagra` is no longer featured. Renaming that record is a manual data step
   for the shelter or a CMS editor.
5. The rename write filter now also requires `starterLockedAt` and `NOT_MINTED_FILTER` (token.stellar,
   token.sei, token.evm empty), so a mint landing between the read and the write still freezes the name.
6. Moderator reset or rename sets `nameChangedAt: now` instead of clearing it (decision #22 above).
7. `NAME_REPORT_REASONS`, `NAME_REPORT_STATUSES`, `NAME_MODERATION_ACTIONS` and `NAME_REPORT_NOTE_LIMIT`
   moved to `shared/name.ts`; the backend schema re-exports them and the CMS API imports them.
8. `grantPack` wraps the pick and adoption: an unexpected error marks the order `FAILED_GRANT`
   (`ADOPT_FAILED: <message>`) and refunds it once (spend taken back), unless the order was already
   COMPLETE when the error happened. Applies to Stellar `POST /web3/confirm` and Stripe `confirm-payment`.
9. `backfill-spent-usd.js` writes the estimate to `spentUsdLegacy` (set once, `spentUsdLegacyAt` guard)
   and never touches `spentUsd`, which stays verified-only. `leaderboardSpentUsd()` adds the two.

Shared vectors: 154 (were 133 before the review fixes).
