## What was built

### Storefront client (G13 steps 4-5)

- `client/api/cat-api.ts`: `CAT_API.storefront()` sends every `/cat/sale` response through
  `parseStorefrontDetailed` (shared contract). It never throws and never returns an array. A failure
  comes back as data, with `failure` set to `network`, `http`, `malformed_json` or `shape`.
  `catsForSale()` returns a Record even on a 500. The old `cat-api.ts:111-115` returned `[]`. That is fixed.
- Also fixed in `cat-api.ts`: `CAT_API.cats()` (`/user/cats`) now always returns an array.
  - Before: a non-array body crashed `Base.tsx:114` (`userCats?.filter is not a function`) and blanked HOME.
  - The resilience harness found this.
- `client/hooks/useStorefront.ts`: the one storefront query.
  - Shared key `["storefront"]`, 45 s stale time to match the backend cache.
  - `storefront_degraded {reason}` fires once per fetch, not once per consumer. A failure is reported
    on every fetch. A usable but partial response (`reason: "partial"`, the legacy shape) is reported
    once per page session, so the guardrail counts sessions on an old backend, not refetches.
  - When a refetch fails, the last good cats stay on screen.
  - Role helpers take `_meta.shelters` roles. When `_meta` is absent or names no shelter for a role,
    they fall back per role to today's slugs (`rozine-pedute` partner, `token-tails` house).
- `client/constants/utils.ts`: new `sample(items, count, random)`, a partial Fisher-Yates on a copy.
  - It never mutates its input and accepts a missing list.
  - Also added `seededRandom(seed)`.
  - `getRandomObjectsFromArray` is now a non-mutating alias. The known bug is fixed: the old in-place
    `sort` reshuffled the query cache and crashed on `undefined.sort`.
- `client/components/shelter/Shelter.tsx`:
  - Zones come from the hook through `shelterZones()`. The partner zone takes a sample, memoised on
    one seed per visit.
  - All NPCs go out in one `NPC_SPAWN_BATCH`, using the scene work that has already landed. The
    legacy per-cat `NPC_SPAWN` is no longer sent.
  - Spawning waits for both a trusted response and the scene. The zones are frozen at that moment
    (`spawnedZones`), and both the spawn and the sign read the frozen copy, so a focus refetch after
    the 45 s stale time cannot make the sign disagree with the floor.
  - Empty zones get a night plaque (decision #87). Only the partner zone, which really had adoptable
    cats, is listed under "All adopted, thank you!". Empty house zones are listed under "Back soon".
    The plaque has a close button and fades after 8 s (`EMPTY_SIGN_MS`; no fade under reduced
    motion). In short landscape (`max-height: 500px`) it is a compact corner card, top right, clear of
    GO BACK / HOME and the centre of the play area.
  - A failed load shows a degraded `role="alert"` toast with RETRY. RETRY refetches, and the zones
    fill in when it succeeds.
  - The card handler no longer mutates the cached cat's `type`. It sets a copy instead. This was
    another cache mutation.
  - The known bug is fixed: `Shelter.tsx:103-106` crashed on a missing key.
- `client/components/marketplace/MarketplaceItems.tsx` and `MarketplaceItemDetails.tsx` use roles
  instead of magic slugs. `MarketplaceItems` also has loading ("Loading cats..."), empty and RETRY
  states. `MarketplaceItemDetails` only reads the roles: it has no states of its own, and it reads
  `/cat/sale` through the shared query key, so a detail page opened from the list costs no extra fetch.
- Deleted `client/components/shared/CatsInNeed.tsx`: it was dead code, confirmed by grep.

### SeoHead (F12)

- `components/seo/site.ts` holds the helpers: `siteOrigin()`, `siteName()`, `twitterHandle()`,
  `absoluteUrl()` (built with `new URL()`), `absoluteAsset()` and `articleSitePath()` (`/feed/<cat>/<slug>`).
- `SeoHead.tsx` builds its tags with `buildSeoTags()` (pure and tested):
  - Tags are keyed.
  - `og:image` is absolute, with width and height for the default card (1257x631).
  - Twitter tags appear only with a valid handle, Facebook tags only when configured.
  - The `noindex` prop sends `noindex, follow` and drops the canonical.
  - The legacy `name` and `page` props keep working. A `page` value that is not a path is ignored.
  - The known bug is fixed: `https:/tokentails.com` came from `.replace("//","/")`, and `@undefined`
    came from an unset handle.
- `ArticleMeta.tsx` is deleted. `buildSeoTags` emits the `article:*` tags (published and modified
  time, author, section, tag; empty values skipped) as direct `<meta property>` children of `<Head>`.
  A nested component inside `next/head` is not synced by Next's client head manager
  (`next/dist/client/head-manager.js` updates only meta/link/title/style/script/base elements), so
  the old `<ArticleMeta/>` tags went missing on client navigation and stayed stale after leaving an
  article. The JSON-LD copy ArticleMeta used to duplicate (a missing `/logo.svg`, a made-up rating,
  another site's social links) was removed earlier. `ArticleMicrodata` uses the same helpers.
- Pages adopt the new props in 3f, 4b and 6b.

### CDN sync (F12, decision #59, recommendation "Approve")

- New `.github/workflows/cdn-sync.yml`:
  - Runs on pushes to `main` touching `client/public/**`, or by hand.
  - It first fails if the Spaces secrets are missing, so nothing is uploaded without them.
  - Pass 1: `s3cmd sync` with `Cache-Control: public, max-age=3600`, excluding versioned files.
  - Pass 2: only versioned files (`-vN-`, `.vN.`, `heist-game/build/`), with
    `public, max-age=31536000, immutable`.
  - Never `--delete-removed` (the asset rule).
  - Optional `dry_run`. The dry run also prints the local files the VERSIONED pattern matches. The
    pattern's Heist part is `(^|/)heist-game/build/`, so it matches whether s3cmd compares paths
    relative to `./public/` or with a prefix.
  - `s3cmd sync` skips unchanged files, so new headers reach only new or changed files. A one-time
    `reheader` dispatch input runs `s3cmd modify --recursive --acl-public --add-header` in the same
    two passes, for the files the GitLab job already uploaded.
  - The optional flush runs only with `DO_API_TOKEN` and `DO_CDN_ENDPOINT_ID`.
- `client/.gitlab-ci.yml` gets a DEPRECATED header. Removing it is the deferred #59 settings change.
