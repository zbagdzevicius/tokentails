# 6c: lobby audio, volume and mute settings, suspension-aware playback (G14 "Audio")

Status: done. Nothing committed, deployed or uploaded.

## What was built

1. **Settings store (`client/components/audio/settings.ts`)**
   - Music volume, effects volume and one mute. Defaults are 0.4 for music and 0.6 for effects
     (the old player hard-coded 0.05), not muted.
   - Stored under `tt:audio:v1` in `localStorage`. Every access is in try/catch: a failed or
     corrupt read gives the defaults, a failed write keeps the change in memory for the page.
     Values are clamped to 0..1 with two decimals. Other tabs follow through the `storage` event.
   - The old `gameMusic` toggle key (`"false"`) is read once as `muted: true`, so a player who had
     turned music off keeps it off.
   - `effectsGain(base)` makes the effects volume a master gain over the authored mix.
   - `useAudioSettings()` (`useSyncExternalStore`; the server render uses the defaults).

2. **Music engine (`client/components/audio/musicEngine.ts`)**: one `<audio>` element per page,
   shared by the lobby and the modes. It plays only when all of these hold:
   - the page has had a user input (pointer, touch, key or click; sticky `userActivation` counts).
     The element is not created and the file is not fetched before that input;
   - a track is set and the music gain is above 0 (not muted);
   - no GameModal suspension holds DOM audio;
   - the document is visible (`visibilitychange`, plus `pagehide`/`pageshow` for iOS);
   - the system mute can be honoured on native (`systemMute.ts`).
   A play the autoplay policy refuses (`NotAllowedError`) is retried on the next input. The engine
   also pushes the effects volume and mute to every Phaser sound manager.

3. **Suspension (`client/lib/game/gameRegistry.ts`, plan F3.5)**: `acquireGameSuspension()` (used
   by `useSuspendGame`, so every GameModal) also pauses registered media elements and resumes only
   the ones it paused, and only if they should still play (not muted since, tab not hidden).
   `exemptAudioFromSuspension()` keeps music playing while held: the Settings modal holds one so
   the player hears the volume they set. `setGameSoundSettings` applies the effects volume and mute
   to registered games, including ones registered later.

4. **System mute on native (`client/components/audio/systemMute.ts`)**
   - iOS 16.4+: `navigator.audioSession.type = "ambient"`, so page audio follows the silent switch
     and mixes with other apps' audio.
   - iOS WebView without the Audio Session API: the switch cannot be honoured or read, so music
     stays off. Phaser's Web Audio effects already follow the switch.
   - Android: media volume 0 is the system mute; backgrounding fires `visibilitychange`.

5. **Tracks (`client/components/audio/tracks.ts`)**
   - `LOBBY_MUSIC_TRACK` is the single constant for the lobby theme. The commissioned night theme
     is deferred, so it points at the only track in `client/public/music`:
     `Adam Dib - Over the River Through the Woods.mp3` (2:20, about 550 KB, a gentle acoustic loop).
     When the artist file arrives, add it under `public/music/` and change only this constant.
   - Modes keep their CDN tracks; Purrsuit picks one of its 45 songs per level. The Catnip Heist
     maps to `null`: it runs in its own iframe with its own audio, so the shell stays silent and
     does not play over it.
   - The lobby had no music before this change: `GameMusicPlayer` returned `null` with no mode open.

6. **UI**
   - Lobby HUD (`GameOptionsModal.tsx`, `GameSelect.tsx`): a Settings gear and a mute toggle in a
     column under ABOUT ME, mirroring PROGRESS on the left. They are 44 x 44 px (in px, because
     phones scale rem), on night plates. Mute is a toggle button with the stable name
     "Mute sound" and `aria-pressed`. Placement constants are in `components/audio/hudPlacement.ts`.
     The mute toggle sits outside GameSelect's centred HUD column, because that column's
     transform would otherwise become the containing block of a fixed element.
   - Settings (`components/audio/SettingsModal.tsx`, a `GameModal` panel opened from
     `GameOptionsModal`): Sound (mute, Music volume, Effects volume) and Graphics. The sliders are
     labelled native range inputs (5 % steps, `aria-valuetext` "70%" or "70%, muted"), styled as
     pixel tracks with a square gold thumb and a 44 px hit area.
   - Graphics (`components/audio/GraphicsTierControl.tsx`) uses 6e's
     `components/Phaser/look/settings.ts`: `getRenderTierSetting`/`setRenderTierSetting` for
     Auto/High/Low, and `getReducedMotionOverride`/`setReducedMotionOverride` for a separate
     Reduce motion group (System/On/Off). Each group is a radio group of 44 px segments with
     arrow-key navigation and a roving tab stop. A hint states that the change applies the next
     time a game opens, and, when storage refused, "Saved for this visit only". The control
     re-reads on 6e's `LOOK_SETTINGS_EVENT`.
   - Profile sheet (`GameMusicToggler.tsx`, rendered by `ProfileModal`): the old on/off music
     toggle is replaced by the same sound panel, so sound settings can be reached in a mode too.
   - `MusicPlayer.tsx` (not mounted anywhere today) now goes through the same engine.

## Found, not fixed (outside 6c)

- **With all of `localStorage` blocked, `/game` never leaves the loading curtain.** The Stellar
  Wallets Kit reads `localStorage` unguarded when its module loads
  (`@creit.tech/stellar-wallets-kit/esm/state/values.js`, key `@StellarWalletsKit/activeAddress`),
  and the uncaught `SecurityError` stops the app. The audio code handles blocked storage, so
  `audio.spec.ts` blocks only the audio and graphics keys. Suggested fix (for whoever owns the
  wallet integration): load the kit lazily behind a storage probe, or wrap its import. Add it to
  the client known-issues list (`docs/CLIENT.md`; task 7a owns docs).
- `WheelModal.tsx` keeps its own click and hover `Audio` at 0.5 and ignores the effects volume
  and mute. `Match3Scene.ts` synthesises sounds through its own `AudioContext` (task 6e's file),
  so its tones follow neither the effects volume nor mute. Both are one-line follow-ups with
  `effectsGain`.
- `client/__test__/landing-routing.test.tsx` (6b) and `client/components/Phaser/look/worldLook.ts`
  (6e) had type errors in the working tree during this run. Both belong to tasks running in
  parallel and are not caused by 6c.

## Review fixes

1. HUD column anchors to ABOUT ME's own `top-4` (`calc(1rem + 88px)` and `calc(1rem + 140px)` in
   `hudPlacement.ts`), not the safe area, so it stays attached on notched phones. If ABOUT ME
   gains a safe-area offset, add it to both values.
2. The lobby mute toggle renders only with the profile, like Settings, ABOUT ME and the music
   player (`GameSelect.tsx`).
3. A first tap on a sound control (`data-audio-control`, both `MuteToggle` variants) unlocks the
   engine without creating the element, so muting first never fetches the track.
4. On iOS WebViews without the Audio Session API the Music slider shows a note, linked with
   `aria-describedby`. The engine exposes `musicAvailable`.
5. Button click and hover sounds moved to `client/components/audio/uiSounds.ts` and follow the
   same system mute rule as music (applied once per page through `systemAudioAllowed()`).
6. The Effects slider plays one click at the chosen level 120 ms after the player lets go
   (pointer up, or a key that moves the slider; Tab is ignored).
