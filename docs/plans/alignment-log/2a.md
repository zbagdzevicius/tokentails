## Decisions applied (plan recommendations)

- **#3 Unverified password users:** new accounts need a verified email (`email_verified === true`)
  (`AUTH_ENFORCE_EMAIL_VERIFIED`, default `true`). **Legacy accounts own no uid** (main signed in by
  email only, and `backfill-firebase-uid.ts` skips unverified users), so from the first request
  after this deploy every legacy password user whose Firebase email is unverified gets 403
  `EMAIL_UNVERIFIED` until they verify (plan W1: an unverified token never binds). Neither flag
  changes that. `AUTH_REQUIRE_VERIFIED_EXISTING` (default `false`) only affects accounts that own
  their uid while unverified, which exist only if they were created while
  `AUTH_ENFORCE_EMAIL_VERIFIED=false`. The heads-up email and 3a's verification screen must ship
  **before or with** this deploy (manual steps reordered; 2a third review, finding #3).
- **#4 Deletion:** record anonymised (name "Deleted player", personal fields removed, `deletedAt`),
  Firebase users deleted, starter removed, other cats released (`owner: null`, stake cleared,
  `releasedAt`), audit record in `accountdeletions` (ids and counts only), Apple revocation when
  `appleAuthorizationCode` is sent and `APPLE_*` keys are set (else skipped and logged). The custodial
  wallet stays on the record (it can hold NFTs and funds); removing it is a manual support step.
  Released cats are copies of catalogue cats, so they do not return to `/cat/sale` (the catalogue
  original is still for sale).
- **#5 No Identity Platform:** disposable-domain check for new accounts and promotions
  (`DISPOSABLE_EMAIL_DOMAINS` extends the list); App Check on `POST /user/guest/session`. Gmail
  aliases count as one inbox for abuse checks (`emailCanonical`, third review finding #5).
- **#7 Guest Tails:** pending only, lifetime cap 2000 (`GUEST_TAILS_LIFETIME_CAP`), credited on
  promotion or merge.
- **#8 Guest starter on merge:** dropped.
- **#9 Allow-list:** 1b's list plus `POST /user/guest/session`, `DELETE /user/guest`. `POST /user/starter`
  and `PUT /cat/:id/name` are for G3 (they do not exist yet).
- **#10 Soft nudges:** client only (nothing on the backend).
- **#11 Idle cleanup:** 30 days (`lastSeenAt`, or `createdAt` when never seen); guests in a merge are
  kept; Game rows stay as play history.
- **#12 Referral:** once per referred account, ever, within 7 days of `promotedAt` (or `createdAt`
  for older accounts); `referredBy` set once; existing multi-referred accounts unchanged.
- **#13 Traction:** guests and guest starters excluded; `guestSessions` separate.
- **Interpretation, "uid mismatch 409" (G9 acceptance):** with `firebaseUids[]` a verified second uid
  is attached, not refused (2.13 #1). The 409 cases are a uid on a guest doc whose email belongs to
  another account (step 1b) and a unique-index clash while binding (E11000).

## Review fixes (2a review, 9 findings)

1. **HIGH, fixed: provider trusted as proof of email (account takeover).** `isVerifiedToken` is now
   `email_verified === true` only; `scripts/backfill-firebase-uid.ts` `isTrusted` is
   `emailVerified === true` only. Deviation from F5.2 1a. Specs: provider google.com/apple.com with
   `email_verified` false or missing, against a uid-less doc and a bound doc: 403, nothing written
   (`email-binding.hotfix.spec.ts`), and the backfill classifies such a user `skippedUnverified`.
2. **Fixed: promotion deadlock for accounts without a Firebase user.** `promoteGuest` 1b binds on
   the server when the colliding account has no uid, or only uids whose Firebase user is gone
   (`IFirebaseIdentity.userExists`): claim the merge, `$pull` the uid off the guest, set it on the
   account (conditional on its uids being unchanged), run the merge (the Firebase user is kept),
   return the account with `promotedNow`. If the account already merged a guest in 30 days it is
   bound anyway and the guest progress is erased. Specs in `identity-resolution.spec.ts` and on real
   MongoDB in `identity-mongo.spec.ts`.
3. **Fixed: deleted account re-created by a still-valid token.** `createRegistered` and
   `createGuestSession` (insert paths only) call `firebase.userExists(uid)` first and answer 401
   when the user is gone. Other Firebase errors count as existing (an outage never blocks sign-up).
4. **Fixed: merge and promotion racing.** The promote filter requires `mergedInto: {$exists: false}`
   (409 when mid-merge); every merge step re-reads the guest as a guest claimed by this target (409
   otherwise); `done` deletes cats and Firebase users only while `{isGuest, mergedInto, mergeState:
   'done'}` still matches.
5. **Fixed: regex email scan per unverified request.** With `AUTH_ENFORCE_EMAIL_VERIFIED` on, an
   unverified token without a uid doc gets 403 before any email lookup.
6. **Fixed: deleted accounts ranking and earning.** `deleteAccount` zeroes the board fields
   (`BOARD_FIELD_RESET`: tails, monthTails, catnip and paw-match arrays and counts, season event).
   Chosen over a `deletedAt` board filter because partial indexes cannot express `$exists: false`.
7. **Fixed: `promotedNow` lost on non-profile promotions.** Persisted one-shot `promotionUnnotified`,
   cleared atomically by `GET /user/profile` (`UserService.claimPromotionNotice`).
8. **Recorded: `tailsEarned`** (field does not exist). `monthTails` is now credited too.
9. **Fixed: E11000 while re-parenting Game rows** (future Heist unique index): the rows move one by
   one and a duplicate guest row is deleted, so the merge never loops in `started`. **Fixed:** the
   guest feed clamps `pendingTails` at the cap with an update pipeline (no CAP + FEED - 1 overshoot).

## Review fixes (2a second review, 7 findings)

All seven verified against the code; none rejected.

1. **Fixed: the Firebase-less bind path lost Heist progress and cleared levels.**
   `UserService.guestLifecycleDeps()` passed plain `recomputeGameTotals`; it now passes
   `recomputeAfterGuestMerge(repository, users)`, the same callback as the controller's
   `guestDeps()`, so both merge paths give one result. Spec: a guest with `heistScore`,
   `heistStars` and `match3Cleared` binds to a Firebase-less account; the account has the `$max`
   scores, OR-ed stars and the cleared flags (`identity-resolution.spec.ts`). The in-memory model
   gained `$bit` for it.

   `resolveRegistered` to `promoteGuest` and `bindGuestToFirebaselessAccount`; both `check` before
   any write and `record` only after a real promotion or bind. Specs: the 11th promotion from one IP
   within an hour is 429 and the guest doc is byte-for-byte unchanged, another IP still promotes;
   the bind is 429 before any write.
3. **Fixed: without `TRUST_PROXY` every sign-up shared one bucket.** `IpWindowThrottle` fails open:
   `isUsableClientIp` rejects `'unknown'`, loopback, RFC 1918, CGNAT 100.64/10, link-local and
   IPv6 ULA/link-local (IPv4-mapped IPv6 unwrapped); such an address is neither checked nor
   recorded, and one warning per process is logged. The Heist replay guard
   (`user/heist/heist-ip-throttle.guard.ts`, not mine) still buckets by `requestIp`; its owner may
   want the same rule. Spec in `identity-referral-deletion.spec.ts`.

   Manual step 11 below. Index builds from autoIndex are app-wide Mongoose config (`app.module.ts`,

5. **Fixed (wording): the duplicate-user race entry** now says "fixed per process; fully fixed once

6. **Fixed: `DELETE /user/me` hid released shelter cats.** `account-deletion.ts` `releaseCats`, cat

   `IFirebaseIdentity.deleteAnonymousUsers`: `admin.auth().getUsers` in batches of 100, deletes

Minor notes from the review, not changed: referral credits do not increment `monthTails` (the

## Known limitations

- Before the unique-index migration, two replicas can each insert a doc for the same new uid in the
  same instant (an upsert without a unique index is not atomic across servers). Within one server
  single-flight prevents it. The migration closes it.
- The per-IP throttles are in-process (limit x replicas). Behind a proxy without `TRUST_PROXY` they
  fail open (no per-IP limit on sign-ups and guest sessions) until the hop count is set.
- The case-insensitive email fallback is an anchored regex on the email index. It runs only when the
  uid and the exact spellings miss, and it is switched off by `IDENTITY_BACKFILL_DONE=true`.
- Idle-guest cleanup leaves the guest's Game rows (play history) pointing at a deleted user, like
  any deleted account. `DELETE /user/guest` deletes them.
- The merge-resume cron keys on `updatedAt` (5 minutes); a merge the client is still running is
  never resumed twice at once because every step is conditional.
- The daily cat hunger reset still covers guest starters on purpose, so guests can feed daily; the
  reward is pending and capped.
