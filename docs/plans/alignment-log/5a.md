## Published contract (import these)

### Events (`client/components/Phaser/events.ts`)

| Event | Payload | Who sends | Meaning |
|---|---|---|---|
| `RUN_READY` | `IRunReadyEvent { isRestart?, mode?, level?, guards?: number \| null }` | scene | Cat on the map, frozen; the gate may show. `guards: null` = unlimited, absent = mode has none. |
| `RUN_BEGIN` | `IRunBeginEvent { isRestart?, mode?, level? }` | scene | First input consumed; the run started. **The only signal for `gameRun.start` (`game_start`).** |
| `GAME_RESTART` | `IGameRestartEvent { cat?, isRestart: true }` | GameContext (`tryAgain`) | PLAY AGAIN on the same level. Scenes restart themselves on it. |
| `LIFE_LOST` | `ILifeLostEvent { guardsLeft: number \| null, cause?, mode?, level? }` | scene | A soft death (Paw Guard spent). Never saved. |
| `RUN_HINT` / `RUN_HINT_DONE` | `IRunHintEvent { hint, text, kind: "prompt" \| "teach" }` / `{ hint, result }` | scene | First-run hint shown / done. `RunHint` (in `RunGate.tsx`) renders it. |
| `GAME_STOP` | `IGameStopPayload` = `IGameStopEvent` with **required** `outcome: "won" \| "died" \| "timeout" \| "quit"` | scene | Run ended. |
| `GAME_START` | deprecated | ShelterScene only | GameContext keeps `isStarted` on it but sends no `game_start`. |

`GameStopOutcome` is now `LiveGameOutcome` from the shared enums (adds `timeout`).
`IGameStopEvent.outcome` stays optional so hand-built panel props (tests) compile; the pushed type
`IGameStopPayload` requires it. Match3Scene's push needs `outcome` (5c).

## What was built

1. **RunGate** inside a `pointer-events-none fixed z-[35]` layer above the mobile controls, gate at
   `z-gate`, X (`CloseButton "Leave level"`) above it. Full card on the first visit to a level, pill
   after. Card is `role=group` with an `aria-live` line. The scene turns Phaser key capture off while
   the gate is open, so Tab reaches Back and Enter/Space on Back go back (Back stops propagation);
   Esc and Android back (`@capacitor/app` `backButton`) go to the level map. Card sits below the cat
   on desktop and at the top on phones/landscape.
2. **GameContext**: `outcome` resolved and sent to `/live`; `decideSave` (won always, hard death only
   on a new best, `quit` never, no session never); points clamped to the cap (1a bug #4); hard deaths
   keep `isStarted` (DeathCard covers the mode, no GameSelect flash); `lastOutcome`; `tryAgain` sends
   `GAME_RESTART` (+ `gameRun.restart()`), never `GAME_START`; `game_start` only on `RUN_BEGIN`;
   `saveNudge.firstClear()` and `ftue_first_clear` on a first clear; local clears cached; cleared
   arrays from the `/live` answer merged into the profile; first-time routing (no clears in a scored
   mode -> level 1); haptics on soft death, hard death and clear.
3. **Purrsuit scene**: frozen spawn (cat lands, does not run) until the first input, which is
   consumed; first-visit freeze at the first spike with "JUMP!", cat snapped to `promptFreezeX` so the
   answer jump is the same at every fps, plus a guarded jump until it lands past the run; slow-mo
   teach (0.35x on time, tweens, anims and physics, ended on real time) for the first of each new
   mechanic (trampoline, gravity, flight, geometry, direction, mid-air, portal, speed, platform),
   freeze-and-prompt under reduced motion; no speed ramp (there is none, none added); Paw Guard soft
   deaths through one `onHazardHit` for both spike paths, checkpoint restore
   (`PlayerMovement.snapshot/restore` + scene flags, clouds, pickups and power-ups after the
   checkpoint respawn, score back to the checkpoint's), respawn frozen until the next input with a
   900 ms grace; `endGame` keeps `catDto`; `GAME_START` no longer listened to (no teleport);
   goal end fires once.
4. **Level map**: unlock rule over the full list from `catnipChaosCleared` (grandfathered points > 0
   when the field is absent, local clears as a cache); INFINITE locked until 1-1; START HERE; CLEARED
   counter; all-cleared notice only when every level is cleared, no promise of new levels; the
   "MORE COMING SOON" countdown (to a past date) removed; per-level caps from the shared table;
   Assists panel ("Extra guards", "Slow-mo on every hazard", not flagged, #71).
5. **DeathCard** (`alertdialog`, RETRY focused, focus loop, Esc -> level map), contextual tip by
   cause, "Extra guards" suggestion after three hard deaths on a level, "Run over" for INFINITE.
   RETRY to the next RUN_READY measured at 23-41 ms in Playwright.
6. **MobileControls.ts:44** labelled fix (ignores only controls, dialogs and the canvas). Device
   pass deferred to the native-release checklist.
7. **Night ProgressBar** (was red `animate-colormax`), clear of the X.

## Review fixes (5a review, 10 findings, all accepted)

1. **Per-player clears, server is the truth.** `ftue-store` v2: clears, pending clears and hard
   deaths live under `players[owner]` (`setOwner(profile._id)`, set by GameContext during render,
   silent); gates, hints and assists stay per device. A v1 blob keeps gates/hints/assists and drops
   its ownerless clears/hard deaths. `addLocalClear` marks the clear pending; GameContext calls
   `settleClear` when `/live` answers (ok or failed); pending expires after
   `PENDING_CLEAR_TTL_MS` (2 min). `clearedFlags(profile, mode, local, pending)`: over a server
   array only `pending` counts; without one (signed out, older backend) local clears count.
   Callers that pass no `pending` keep the old cache rule: **request to 5b** — pass
   `ftueStore.pendingClears(PIXEL_RESCUE)` in `PixelRescue.tsx`, `PixelRescueLevels.tsx` (via
   `cupidLevelStates`) and the `localClears().includes` check in `PixelRescueScene.ts:319`, and
   update `pixel-rescue-ftue.test.ts` "adds local clears as a cache". Per-owner keys already stop
   the cross-account leak there.
2. **Extra guards** only on uncleared, non-infinite levels (`pawGuardAllowance`); INFINITE ends
   never count as hard deaths and the DeathCard never offers the assist there. Assist copy says
   "a level you have not cleared".
3. **Gate guard line** built from the count (`guardsLineText`: "×6: 6 slips", "1 slip"), and
   "No Paw Guard on Infinite" via the new `endless` prop.
4. **Handoff starter shield**: the unused module-level flag (`takeHandoffStarterShield`) is
   removed; Cupid derives the shield from the cleared state (`starterShieldFor`, 5b). Documented
   in `handoff.ts`.
5. **MobileControls**: tap-to-jump bails while a modal suspends the game (`isGameSuspended`) and
   handles only taps on `#game-container` / `[data-run-surface]` (the Purrsuit layer) that are not
   controls or the canvas (`isRunSurfaceTap`), so backdrops, toasts and overlay scrolling are not
   `preventDefault`ed. Device pass still deferred.
6. **First-time routing** waits until the progress is known: `ready`/`guest`, or `signed-out` with
   a profile; without the auth context, a profile.
7. **Gate Esc / Android back** ignore the key when `defaultPrevented` or a dialog is open.
8. **Guided jump** protection ends when the cat is past the run (grounded or not) or after
   `GUIDED_JUMP_MAX_MS` (1500 ms, scene clock) — `guidedJumpOver`. The pure test that the jump from
   `promptFreezeX` clears the 1-1 run without immunity already existed (`jumpClears`, plus the
   frame-stepped 30/60/120 fps model); a named test was added next to the new ones.
9. **DeathCard** shows "New best" at once, "New best, saved" after `/live` resolved, "New best,
   not saved" on failure (`saveState`, `newBestLine`).
10. "Turn it on" moves focus to RETRY; the pill's guard count is sr-only text; `setGameType(mode,
    level)` opens mode and level in one call with one `select` (the hand-off uses it).

Outside 5a's list: `client/__test__/onboarding-store.test.tsx` (hand-off assertion now expects
