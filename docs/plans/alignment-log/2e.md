## What was built

### `client/components/Phaser/look/` (no Phaser runtime import; safe in Jest and SSR)

| File | What it does |
|---|---|
| `makeGameConfig.ts` | The one config builder used by all five configs. Backing store `round(innerWidth x dpr)` by `round(innerHeight x dpr)`, `scale.mode NONE`, `zoom 1/dpr`, canvas CSS size forced to the viewport, Arcade bounds kept at the CSS size. `registry.set('canvasPixelRatio', dpr)` and `renderTier`. A debounced (150 ms) `resize`, `orientationchange`, `visualViewport` and DPR media-query handler resizes the backing store, rescales every camera when the ratio itself changes, and emits `LOOK_RESIZE` on `game.events`; a failing resize never throws out of the handler; removed on game destroy. Caller callbacks still run. Also a dev/E2E-only `window.__ttGames` hook (below). |
| `tier.ts` | LOW/MID/HIGH from `deviceMemory`, `hardwareConcurrency`, Save-Data. Caps: LOW 2 (1.5 when `deviceMemory <= 4`), MID 2, HIGH 2; 3 only behind `ALLOW_DPR_3 = false`. Auto/High/Low setting in `localStorage["tt-render-tier"]`, every access in try/catch, applied on the next game mount. |
| `pickZoom.ts` | Pure integer zoom picker: hub 12x8 tiles, platformer 14x9, measured in backing pixels; targets swap in portrait. Not applied yet (task 6e); `ZOOM` and `ZOOM_PIXEL` are untouched. |
| `rng.ts` | Seeded mulberry32 with `between`, `float`, `pick`, `fork`; FNV-1a `hashString`. |
| `textureKeys.ts` | `player-cat-${_id}-${shortHash(spriteImg)}`, `npc-${_id}-${shortHash(spriteImg)}` (hash added in the second review round), animation keys `${textureKey}_${ANIM}`, loadable-URL check, HTML escape for the speech bubble. |
| `loadTextures.ts` | Race-free `loadSpritesheets`: waits for an idle loader, one pass per batch, settles each key on its own `filecomplete`/`loaderror`, reports loaded only if the texture exists, replaces a key whose URL changed (drops its animations), times out, and resolves on scene shutdown. `removeTexture` removes a texture and its animations. |
| `camera.ts` | `setCssZoom`, `cssZoom`, `setCssScroll` (old view centre), `fitCssCamera` (screen-space layouts, letterboxed on resize). |
| `text.ts` | Default-resolution `Text` objects get `min(3, max(dpr, camera zoom))` resolution and a LINEAR filter; texts with their own resolution are left alone. G12's `ttText` supersedes it. |
| `registry.ts` | Registry key constants and `getCanvasPixelRatio(scene)`. |

### Scenes and objects

- All five configs (`base`, `shelter`, `CatnipChaos`, `PixelRescue`, `Match3`) use `makeGameConfig`
  and keep 1c's `registerGame(game)`.
- Every camera zoom and scroll is multiplied by `canvasPixelRatio` (`setCssZoom`/`setCssScroll`) in
  BaseScene, ShelterScene, CatnipChaosScene and PixelRescueScene, and in the PixelRescue tutorial
  tweens. The visible world is unchanged at every viewport; see Checks.
- Match3 lays out in CSS pixels (`viewWidth/viewHeight = scale / dpr`), maps them through
  `fitCssCamera`, reads pointers through the camera, and on `LOOK_RESIZE` fits the built board into
  the new size (letterboxed). The full relayout is G12's `layoutHud()`.
- The player cat loads through `catbassadors/objects/playerCatTexture.ts` in every scene that loads
  it (Home, Shelter, Purrsuit, Cupid): id key, `isSamePlayerCat` by key instead of by name, the
  previous player texture and its animations removed on re-skin, a stale load for an older pick
  dropped, and a failed sheet reported instead of spawning.
- `Catbassador.Cat`, `NpcCat` and `base/objects/Cat.ts` (`CatNpc`) take a texture key, not a name.
  `CatNpc.initAnimations` no longer destroys and recreates the global `PlayerAnimation.*` keys; it
  builds `${textureKey}_${ANIM}` once (own change, marked in the file).
- `NpcCat.displayName` shows the cat's name in the speech bubble. `SpeechBubble` escapes the text
  it writes into `innerHTML`. Cat names are user-chosen, so before this a name went into the DOM
  unescaped.

### ShelterScene (G13 step 6) and Home

- `GameEvents.NPC_SPAWN_BATCH {npcs}` is one load pass (`planNpcBatch` + `loadSpritesheets`).
  NPCs are keyed `npc-${_id}-${shortHash(spriteImg)}` (see "Second review round"). Cats without an id, without a usable URL, repeated, or already on
  screen are dropped before loading. A sheet that 404s or fails is skipped, never spawned on
  `__MISSING`, and reported through `reportAppError("npc_texture_missing", ...)` from
  `client/analytics` (the 1e scrubbed, capped path). Every spawn runs in a try/catch that reports
  `npc_spawn_error`. `anims.exists` guards cover the blessing and NPC animations.
- The answer is `GameEvents.NPC_SPAWNED {count, skipped, skippedIds, source}`. Ids only, no names.
- The legacy one-cat `NPC_SPAWN` stays for one release. `NpcSpawnCoalescer` collects the events of
  one task into a batch, so the old producer (`Shelter.tsx`) gets the same single pass. Home's
  `PLAYER_CATS` events are coalesced the same way. `GAME_START` is unchanged, as is the existing
  duplicate `GAME_LOADED` push in `ShelterScene.create`, which was already in HEAD.
- The NPC overlap handler finds the NPC by sprite instead of by texture key (the key is an id now).

## Second review round (2 findings, both fixed)

### 1. HIGH, confirmed and fixed: Home froze when an on-screen NPC was re-sent with a new sprite URL

Cause as reported: `npc-${_id}` had no sprite hash, so `loadSpritesheets` removed the old texture
and animations before the new load, while the on-screen `NpcCat` still drew from them. On a 404 the
sprite was never replaced; the render loop died with `TypeError: Cannot read properties of null
(reading 'resolution')`. Re-verified: with the fix reverted, the new e2e reproduces exactly that
console TypeError and a frozen NPC texture.

Fix (the review's preferred option plus the minimal guard as a second layer):

- `textureKeys.ts`: `npcTextureKey` is `npc-${_id}-${shortHash(spriteImg)}` (also used by
  `planNpcBatch`). **Decision #39 amended**: both key schemes now carry the sprite hash.
- `BaseScene.spawnNpcs`: the new sheet loads under its own key beside the drawn one. After
  `removeNpcById` + `createNpc` succeed, the old key's texture and animations are removed with
  `removeTexture(this, oldKey, NPC_ANIMATION_NAMES)` (`retireNpcTextures`), but only when no NPC or
  the player cat still draws from it and no unsettled batch is loading it (`npcKeysInFlight`). A
  superseded send's sheet is retired the same way; `spawnCat` retires the NPC sheet of the cat that
  became the player.
- `loadTextures.ts`: new `isInUse(key)` option. A texture that a live sprite uses is never removed
  to load a different URL under the same key; that request is reported as failed and the old
  texture stays. Passed by `BaseScene` (drawn NPCs and player) and `ShelterScene` (drawn NPCs).

Tests: Jest `texture-keys.test.ts` (NPC re-skin is a new key; with `isInUse` nothing is removed
before or after the load settles; a 404 or valid re-skin loads beside the drawn key without any
`textures.remove`). E2E `home: re-sending an on-screen NPC with a new or a 404 sheet never drops its
texture` (the review's PROBE3, plus a slow valid re-skin: old texture drawn for the whole load, then
exactly one `npc-<id>-*` key left).

Test gap closed in `render-foundation.spec.ts` (the shared fixtures are outside my owns list, so
the check lives in this spec): every test fails on a console `TypeError` /
`Cannot read properties of null|undefined`, and an `afterEach` checks `game.loop.frame` still
advances. This immediately found a second real crash:

- **Bug fixed (Cupid Cat / PixelRescueScene.update):** when a re-skin restarts the scene,
  `spawnCat` sets `this.cat = undefined` and queues `scene.restart`; the frame in between ran
  `this.physics.overlap(this.cat!.sprite, ...)` for the crate, heart coins and shields and logged
  `TypeError: Cannot read properties of undefined (reading 'sprite')`. Those three overlaps are now
  guarded on `this.cat`. Pre-existing code (the `cat = undefined` line is in HEAD); it surfaced
  because the 2e restart-payload fix made re-skins actually restart.

### 2. LOW, confirmed and fixed: Paw Match e2e flaky under parallel workers

`expect.poll` timeouts on the resize/rotation polls raised from 10 s to 30 s, and the file runs
its tests in order within each project (`test.describe.configure({ mode: "default" })`, not
`serial`, so one failure does not skip the rest). Projects still run in parallel.

## Review round 3 fixes

Five findings, all verified; four fixed in code, one (docs ownership) carried as an open item.

1. **Shelter NPC test flake (fixed).** The cause was not dev-server noise, contrary to the earlier note.
   BaseScene (Home, which `enterMode` passes through) sent its own-cats `NPC_SPAWNED` with
   `source: "legacy"`, and the test summed it into the Shelter total (4 expected, 6 seen).
   `INpcSpawnedEvent` now carries `scene: "BaseScene" | "ShelterScene"`, and BaseScene sends
   `source: "player-cats"`. `legacy` again means only coalesced single `NPC_SPAWN` events. The
   test waits for and counts only `scene === "ShelterScene"` events. Correction to the third-pass
   note: the 2 failed tests in its first full run were this race, not the dev server.
2. **ShelterScene `CAT_SPAWN` listener leak (known bug, older than 2e; fixed).** The `destroy` handler
   now removes `catSpawnCallback`, and `spawnCat` returns early once a `sceneDestroyed` flag is set
   (the flag, not `sys.isActive()`, because that is false during `create()`, which spawns the first
   cat). New e2e test `shelter: leaving it drops its CAT_SPAWN listener`. It wraps the scene's
   `spawnCat`, leaves the Shelter, then zeroes the counter just before sending the probe, because
   `Shelter.tsx` pushes `CAT_SPAWN` to the live scene while it mounts. A mutation check (listener
   removal taken out) fails it every time; with the fix it passes 8 of 8 across repeated runs.
3. **Cupid hint breakpoint (fixed).** `PixelRescueScene.showFirstSeenHint` read `scale.width`,
   which is backing-store pixels since F10. It now uses `cssViewSize(this).width`, a new helper in
   `look/registry.ts` with a Jest table in `__test__/look-registry.test.ts`. A sweep of `scale.width/height`,
   `cameras.main.width`, `game.config.width` and `canvas.width` in Phaser code turned up no other
   unconverted reads (Match3 already divides by the ratio; `look/camera.ts` divides by the ratio itself).
4. **Before/after screenshots (fixed).** The per-mode test saves
   `build/<mode>-<project>-before.png` and `-after.png` (after the resize/rotation) for all five modes.
   I reviewed shelter-mobile-390 and cupid-desktop-1440: the same world framing as before,
   HUD in place, sharp sprites. The optional "same world at ratio 1 and 2" check is not added: a
   page cannot change DPR mid-test, and within one run the check would repeat Phaser's own math.
5. **Known-issue docs (open, outside 2e's files).** `docs/CLIENT.md` "Known issues" has no entry
   for CatNpc clobbering global `PlayerAnimation.*` keys or for the unescaped NPC name in the speech
   bubble, so it has no stale entry. Plan section 7 rows "Name-keyed Phaser textures and animations"
   and "CatNpc overwrites global animation keys" still read "New" and should be marked fixed by 2e.
   The doc owner should also add a "Fixed in 2e" note to CLIENT.md covering both, plus item 2.

Not changed (reviewer's lower-priority notes, accepted as-is): a camera zoom tween running during a
ratio change corrects itself when the tween ends. `NEXT_PUBLIC_E2E=1` builds expose `window.__ttGames`
and must never be deployed.
