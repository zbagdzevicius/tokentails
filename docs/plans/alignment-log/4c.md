### Account gating (decision #9, applied as recommended)
`client/hooks/useAccountAction.ts` (new, outside my owns list, additive): `runWithAccount(reason,
action)`. Registered accounts run at once; anyone else gets `requireAccount(reason)`, the action
runs after `signed-in` (once React committed the account, so refs hold the account profile), and
`dismissed` does nothing. No provider on the page (`/packs`) keeps the old flow.

| Action | Reason (sheet title) |
|---|---|
| Codex tier, challenge and milestone claims | `claim-rewards` |
| Daily Spin (before any redeem request) | `claim-rewards` |
| Quest claims (the partner link still opens from the tap) | `claim-rewards` |
| Stake reward claim | `claim-rewards` |
| Stake a cat | `adopt` |
| Packs buy, the checkout itself (`PurchaseAccountGate`), Stellar connect and transfer (loot box too) | `purchase` |
| Invite link (`GET INVITE LINK`) | `share` |
| X and Discord linking | `sign-in` |
| Ticket send and MY TICKETS (a guest's tickets are never fetched) | `support` |

Handlers that may run after the sheet read the profile and `setProfileUpdate` through `useLatest`,
so they never write the guest profile back over the account's.

### Profile account section
- Guest: SAVE PROGRESS (`requireAccount('save-progress')`) and ERASE GUEST PROGRESS (confirm step,
  then `eraseGuest()` from the auth runtime, i.e. `DELETE /user/guest` and a fresh guest).
- Account: Logout and DELETE ACCOUNT (confirm step, then `requestAccountDeletion`): on iOS with an
  `apple.com` provider a fresh Sign in with Apple authorization code is fetched first
  (`signInWithApple({skipNativeAuth:true})`); cancelling that prompt cancels the deletion. Then
  `USER_API.deleteMe(code)` and sign-out. Decision #4 (anonymise, delete Firebase user, release cats)
  is the backend's (task 2a); the confirm copy states it. This replaces the old support-email toast.
- RENAME {cat} for the starter (`isStarter`, a real `_id`, not the `guest-starter` template) opens
  4a's `RenameSheet` (lazy, `next/dynamic`), and the profile cat takes the new name.

## Decisions applied
- #9 Guest allow-list: approved as recommended; the gating table above.
- #4 Account deletion semantics: as recommended (backend side by 2a); client adds a confirm step and
  treats a cancelled Apple re-auth as "not deleted".
- Own call: during the Packs checkout a scrim tap no longer closes the modal, and while a payment
  is confirming (Stripe `isProcessing`, a Stellar transfer pending) the X is aria-disabled and Esc
  does nothing; before and after that the X and Esc close it.
- Own call: Logout is no longer offered to guests (there is nothing to log out of; ERASE replaces it).
  Every signed-in, non-anonymous user gets Logout (also while the profile loads, failed or waits on
  email verification); DELETE ACCOUNT only when the account is `ready`.
- Own call (plan G9 "popups from the tap"): actions that open a popup or share sheet (GET INVITE
  LINK, wallet connect, the Stellar Buy Now) run synchronously from an account's tap; a guest gets
  the sheet and, once signed in, a toast asking to tap again. Plain API actions still continue on
  their own after `signed-in`.
