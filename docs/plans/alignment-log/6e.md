## API for other tasks (stable)

`client/components/Phaser/look/settings.ts` (task 6c imports this):

- `getRenderTierSetting(): "auto" | "high" | "low"` and `setRenderTierSetting(value): boolean`. Key `tt-render-tier`. The return value is true when storage kept the setting and false when only memory did.
- `getReducedMotionOverride(): "system" | "on" | "off"` and `setReducedMotionOverride(value)`. Key `tt-reduced-motion`. `isReducedMotion()` combines the override with `prefers-reduced-motion`.
- `getLookVersionOverride()` and `setLookVersionOverride("v0" | "v1" | null)`. Key `tt-look-version`. It also reads 6d's spelling `tt.lookVersion` as an alias.
- Every change fires a `tt-look-settings` window event (`LOOK_SETTINGS_EVENT`).
- All of these work with storage blocked: `look/storage.ts` keeps the values in memory for the page. They take effect on the next game mount.

`client/components/Phaser/look/capture.ts` (for 6d's capture driver) is compiled in only when the build sets `NEXT_PUBLIC_CAPTURE=1`. A page that sets `window.__TT_CAPTURE_SEED__` (a string) before boot gets `window.__TT_CAPTURE__` with these members:

- `seed`
- `games()`
- `freeze(game?)`
- `step(frames, dtMs = 1000/60, game?)`, which advances fixed-delta frames from t = 0 and renders each one
- `state(sceneKey?)`

The seed drives fireflies, stars and the procedural plates. Gameplay randomness is untouched; the driver seeds `Math.random` itself.

Each world scene exposes `lookState()` with these fields: version, preset id, tier, zoom, tiles (`v0`, `night` or `wash`), backdrop, plateSet, plates, lights, fireflies, halos, glow and reducedMotion. Both e2e and the capture driver read it.

## What was built (`client/components/Phaser/look/`)

| File | Role |
|---|---|
| `manifest.ts` | Parses 6d's `public/look/manifest.json` (schemaVersion 1: `presets`, `tilesets`, `plates`, `purrsuitFamilies`, `backdrop`) and drops junk and unsafe URLs. Resolves the version in this order: override, then manifest `lookVersion`, then default `v1`. Holds the fetch cache that the React side shares. |
| `presets.ts` | One preset per scene: `home` (moonlit night, hub-night), `shelter` (dusk, hub-dusk, #49), `cupid` (cupid-night), and `purrsuit/<family>` for every family including ENDLESS `combined` (#50). Each preset carries its palette from `design/tokens.ts` and its zoom preset (hub or platformer). |
| `worldLook.ts` | The per-scene runtime. `preloadWorldLook` queues the manifest once per game; when the manifest is not cached yet, its `filecomplete` queues the night skin, any extra tilesets (the Shelter signs) and the plates by name. `beginWorldLook` returns `tilesetKey` and `extraTilesetKey`; for v1 these return the night skin texture at the same indices. `dress()` installs the camera rig in both versions. In v1 it also installs the backdrop, point lights, fireflies and vignette, and hides the manifest's `backdrop` gids (104, the full-view water fill in `decorations`; drawing only, the tile data stays). `follow()` and `attachCat()` complete the API. |
| `cameraRig.ts` | Takes an integer `k` from `pickZoom`: hub 12x8, platformer 14x9, with portrait swapping the targets (#55: portrait is allowed and keeps the swap). Sets bounds from the map extents plus 8 tiles of sky, grown to the view when the world is smaller. Follows with lerp 0.12, a deadzone, and a horizontal look-ahead added on top of any offset the scene sets (Cupid's gate offset survives a `startFollow` reset). Re-picks the zoom on `LOOK_RESIZE`. Zoom tweens target whole levels only (`zoomBy`, `zoomHome`). |
| `worldBounds.ts` | `computeWorldBounds` reads Tiled infinite-map chunk extents (`widthInPixels` is wrong for these maps). `cameraBounds` and `dominantSurfaceY` (the ground line) build on it. |
| `backdrop.ts` | A separate scene sent behind the gameplay scene with its own camera; nothing has to be ignored and nothing is drawn through a render target. It holds the far, mid, near and fog plates from the manifest at native resolution, scaled by a whole factor (`max(k, ceil(H / plateH))`), anchored top or bottom per the manifest, and moved by the manifest's scroll factors. Under them sits a sky band ramp with stars and a moon. Reduced motion freezes the parallax. It is removed when the gameplay scene shuts down (unique keys, so a Purrsuit restart is safe). |
| `procedural.ts` | Seeded, horizontally tiling fallback plates (ridge with columns, tree line, foliage with blooms, fog band), used when a plate is not in the manifest or fails to load. |
| `presence.ts` | A contact shadow and a tinted additive halo under every cat (player and NPCs in Home and the Shelter, the player in Purrsuit and Cupid). They are plain sprites that follow on `prerender`, with no render-target filter on MID. Glow (a Phaser 4 filter) is on the player on HIGH only. |
| `ambience.ts` | Point lights at emissive tiles (lamp 21 and candles 213 and 243 by default, or the manifest's `emissive`), capped per tier at 64, 32 and 12, with a gentle flicker that reduced motion turns off. Seeded fireflies, 40, 20 and 8 by tier, frozen under reduced motion. A pre-rendered vignette. No global grade. |
| `textures.ts` | The halo, shadow, firefly and vignette textures, drawn once on canvas. |
| `storage.ts`, `settings.ts`, `tier.ts` | localStorage with a memory fallback. `resolveRenderProfile` uses the memory value when storage is blocked. |
| `capture.ts` | The capture hooks above, registered from `makeGameConfig` postBoot. |

## Decisions applied

- **#49:** Home is a moonlit night (hub-night) and the Shelter is dusk (hub-dusk). Both use the hub night skin.
- **#50:** every Purrsuit family, including ENDLESS, resolves to its own preset and plates (the jest test walks all 97 levels).
- **#51:** there is no remote config. The flag comes from the manifest plus a localStorage override. To roll every web player back without a rebuild, set `"lookVersion": "v0"` in `public/look/manifest.json`. For one device, set `localStorage["tt-look-version"] = "v0"` (or `tt.lookVersion`).
- **#55:** portrait is allowed, and pickZoom swaps the targets in portrait. There is no landscape hint UI in this task; the suggestion copy belongs to the mode screens.
- **#84:** the DPR cap is unchanged (2, or 1.5 on low memory or explicit Low).
- **#52:** no Phaser upgrade. Glow, point lights and filters are rc.5 APIs, and the code checks they exist before using them.

## Limitations and manual steps

- **CDN:** night skins, plates and posters load site-relative from `public/`, not through `cdnFile`. Uploading them to the CDN is deferred; until then production web serves them from the app origin.
- **Native builds:** they bundle `public/`, so on native a manifest rollback needs a rebuild. The per-device override works without one.
- **Reference Android perf gate:** MID p95 ≤ 16.7 ms and LOW ≥ 30 fps are deferred to a device run. Only software-GL sampling is logged here.
- **Rescued and caged cats in Cupid:** they ride a cloud or a crate and get no shadow or halo; only player and NPC cats do.
- **v1 without a night skin:** if a skin is missing from the manifest or fails to load, v1 tints the v0 tiles per layer (`tileWash`) instead of showing day tiles under a night sky. It is never a screen grade.
- **Backdrop parallax lag:** the backdrop reads the world camera one frame late, because the backdrop renders first. This is not visible at the scroll factors used.
- **Docs:** no docs known-issue entry existed for fractional zoom or camera bounds, so none was edited. The docs pass is task 7a.

## Review fixes (task 6e review, 9 findings)

Screenshots after the fixes: `/private/tmp/claude-501/-Users-zygimantasbagdzevicius-me-tokentails-app/5b2edd56-881c-4754-b42e-7d5561832e7b/scratchpad/build/6e-fix/` (`v0-*`, `v1-*`, `resize-*`, `payload-*`, and `motion-v1-*` for full motion).

1. **Hard-edged rectangles in the v1 backdrop.** Fixed with the stop-gap. The new `look/plateCheck.ts` reads each manifest plate's alpha once. It flags a run of at least 16 columns (or 2% of the width) that all end on the same row inside the plate. `backdrop.ts` then draws the procedural plate for that layer. `lookState().platesRejected` lists those layers. Every shipped `*-near-v1.png` has a 108-column straight crop at row 229, so all near plates are replaced; far, mid and fog are clean. The art fix (feathered or silhouette near plates that tile) is still **open for 6d**. Once the plates are re-cut they pass the check with no code change.
   - **Related bug, also fixed:** the procedural near plate exposed a wrong horizon on Home. `dominantSurfaceY` picked the upper floor of `base.json`, so the plate's fill strip covered the sky. The backdrop now takes `majorSurfaces()` (floors with at least 25% of the dominant floor's tiles) and stands on the floor under the view's centre (`horizonFor`).
2. **v1 ground still in day colours.** Fallback applied. The new optional `LookPreset.nightTint` is applied per tile layer to the night skin (never a screen grade): Home `#9590d2` (cool, dimmer) and Shelter `#c9a3bd`. `lookState().tileTint` reports it. The real fix (darken and cool `base/spring-night-v1.png`, especially water and dirt) is **open for 6d**; after it, unset `nightTint`.
3. **Shelter dusk looked like Home night.** Fixed in presets and the backdrop. The `shelter` preset now has `plateTint` `#ffd0c4` on the far and mid plates and a `horizonGlow` (DUSK.horizon, alpha 0.5) drawn between the far and mid plates. 4. **Resizing mid-tutorial undid the zoom-in.** Fixed.

5. **The tutorial zoom step was too big on phones.** Fixed with a stricter rule than the review proposed. The new `canStepZoom(viewWidth, k, steps)` lets `TutorialManager` step in only while at least 10 tiles stay visible across; otherwise it holds the current zoom. The review's "or k >= 3" clause was dropped, because `k` is in backing pixels and a DPR 2 phone can reach 3 while showing few tiles. Desktop 1440 still steps 3 to 4 (11.25 tiles); portrait phones do not step.

7. **Reduced motion detached the procedural plates from the ground.** Fixed. Only `midX` freezes. Vertical placement follows the live `midPoint.y` at factor 1, so the plates sit on the ground line.
