## Interpretations

1. The ceremony opens only for a profile the backend sent (`authStatus` guest or ready) and a
   Firebase user. The client template profile is also "pending", so without this a returning
   player whose auth took longer than 2.5 s would get the ceremony.
2. SKIP after the reveal leaves the optional real-cats step only; the starter is already committed.
3. The reveal's CONTINUE never waits for the save: an offline commit is kept as a draft.
4. `/game?meet=1` for a finished account replays the ceremony; its commit answers 409 and is
   treated as done, so the replay never changes the cat.
5. The lobby beat before the first mode is 1.8 s, with "Up next: Cupid Cat · Day 1" in place of
   MY PETS and PLAY during it.

## Review fixes (round 2)

All ten review findings were checked against the code; nine were fixed, one (#7) is accepted as is.

1. **Slow sign-in showed the lobby first (fixed).** New `components/onboarding/AltarHold.tsx`: once
   the curtain has lifted, while the session is `unknown`/`loading-profile` (or the profile has
   arrived but nothing is decided yet) and the profile says `pending`, Game.tsx covers the screen
   with the altar instead of the lobby. It hands over to the ceremony's `loading` step, or goes away
   when the profile says `done`. The fix also exposed a race in the decision itself. The auth status turns
   `guest` one render before FirebaseAuthContext copies the backend profile into ProfileContext,
   so a finished account behind a slow sign-in got the ceremony. The decision now waits 120 ms
   (`PROFILE_SETTLE_MS`) and checks the latest profile again. If the profile changes first, the
   effect re-runs and cancels the timer. New e2e tests: auth at 4.5 s for a pending guest (altar hold, never the lobby) and for a
   finished account (the lobby with "Whiskers", no ceremony).
2. **SKIP was covered at the reveal (fixed).** The SKIP wrapper is now `z-[410]` (above z-reveal
   inside the dialog's stacking context). The RevealAnimation root is `pointer-events-none` when it has
   children, and only the children wrapper takes pointer events. New e2e test: `elementFromPoint` at
   SKIP's centre is SKIP, and the click ends the ceremony.
3. **A late server name refusal was lost (fixed).** `meetMachine`: CONTINUE, START and SKIP do
   nothing at the reveal while `commit === "pending"`. CONTINUE reads "SAVING…" (busy) and SKIP
   is disabled. Offline still counts as done. `commitStarter` now gives up after 10 s
   (`STARTER_COMMIT_TIMEOUT_MS`, abort), so a hung request ends as offline with a draft and never
   strands the player. Tests: machine "COMMIT_INVALID after done", "a refusal after an early
   CONTINUE", component "holds the reveal", e2e "late refusal with no featured cats".
4. **The lobby hero kept a stale name (fixed).** `HeroCat.replacesId` together with `heroFor()` means the stand-in shows only
   while the profile still shows the cat it replaced. A committed cat, a CatsModal switch or another
   account makes the profile win. `finishMeet` no longer sets the hero. A 409 never sets it, nor does a replay
   unless the server took the commit. `heroCat` is cleared once `refreshProfile()` resolves, and
   `onboardingStore.reset()` runs when the uid changes. A rename through RenameSheet updates the profile, so the
   profile shows the new name. New e2e test: a `?meet=1` replay answered 409 keeps "Whiskers".
5. **A replay forced Cupid Cat 1 (fixed).** There is no hand-off for a replay or a `locked` outcome. Game.tsx
   cancels a pending hand-off when `gameType` is set during the lobby beat. The hand-off clears its own timer before it sets the mode, so this never cancels the hand-off itself.
6. **Silent commit failures (fixed).** `wasKept(result, uid)` in commit.ts. A 401, a 403, a non-NAME
   400, or a missing uid now reports a new `failed` outcome. Game.tsx does not patch
   `onboarding: done` for it and sets no hero. The reveal shows "We couldn't save {name}" with TRY AGAIN
   (machine `RETRY`), and CONTINUE still lets the player go on, with onboarding left pending. When
   the silent retry of a stored draft fails without keeping it, the draft is cleared and the ceremony opens again.
7. **SKIP is not the first Tab stop (accepted, not changed).** SKIP is first in DOM and focus order.
   Each step moves focus to its heading (the name input on the name step), so screen readers
   announce the new step, and Shift+Tab reaches SKIP. Moving focus to the container on each step
   would make SKIP the first Tab, but the step change would then go unannounced. The keyboard e2e test checks the current
   behaviour.
8. **Reveal quality (fixed in code).** With children, RevealAnimation now draws a night-900
   backdrop with a gold radial glow, gold conic rays and gold/cream motes, all CSS. The blue pack art and the
   card frame are gone, so the sprite sits centred. The gold "SCOUT" plate was removed, and "Meet {name}!" is the only
   time the name shows. Card packs (no children) keep the old art. The e2e `shot()` hides the Next dev
   badge (`nextjs-portal`).
9. **`justFinished` was never reset (fixed).** It is cleared in the hand-off's `open()` and when LobbyHero
   unmounts.
10. **Mode guards (fixed, restored).** No other task's log claims the removal, so
    `profile &&` is back on all five mounts, inside their SceneBoundary wrappers. The transient guest profile
    and the template both count as a profile, so guests are unaffected.

## Known limitations

- The e2e curtain timing bounds are strict only in CI; on the local dev server hydration and the
  fixtures' installed clock can delay the lift, so the local slack is wide.
- On landscape phones the real-cats panel scrolls to reach START PLAYING.
- The lobby behind the hero slot is still the daytime sky (G7).
- A reveal that is saving waits up to 10 s on a hung request before it counts as offline.
- A `failed` commit (for example 403) leaves onboarding pending on the server. The ceremony comes
  back on the next visit, which is intended: nothing was saved.
