### Wire contract (for layer 3)

Request: `{ type: 'CATNIP_HEIST', replay: <InputLog as recorded>, platform?, outcome?: 'won', level?: <must equal replay.levelId> }`.
`points`, `score`, `time` are ignored. Responses:

| Status | Body `code` | Meaning | Layer 3 handling (plan) |
|---|---|---|---|
| 201 | none | `{levelId, levelIndex, score, stars, newStars, best, heistScore[8], heistStars[8]}` | saved |
| 400 | `HEIST_REPLAY_INVALID`, `HEIST_NOT_WON`, `HEIST_TRAILING_INPUT` | the log is not a clean win | drop |
| 400 | `HEIST_SIM_VERSION` | the log is from another sim version | purge with a visible message |
| 401 / 403 / 428 | per F5.6 | auth | keep, as F5.7 |
| 409 | `HEIST_DUPLICATE` | this canonical log is already saved (any account) | done |
| 413 | none | body over 64 KB | drop |
| 429 | none, `Retry-After` header | per-IP, per-player or queue | back off |

The digest is `sha256(canonicalLogKey(log))`: sim version, level, seed, tick count and the runs with
adjacent identical inputs merged. The crew is left out (it does not change the simulation), so swapping
cats does not make a "new" run.

## Deviations and choices (with reasons)

- **Global unique digest, crew excluded.** The plan says global unique; the older 3d doc said
  `(user, replayHash)`. Global is what the plan's acceptance needs (409 from any account).
- **Grandfathering for Paw Match uses `match3 > 0 OR match3Score > 0`.** The client unlocks on either, so
  using catnip alone could re-lock a level a player has today (plan G10 risk "no lost unlocks").
- **Array backfill fills null values and repairs malformed `heistStars` only; a missing field stays
  missing** unless `MIGRATION_BACKFILL_MISSING=1`. `/live` creates arrays itself and every reader treats
  missing as zeros, while writing 157 zeros into ~540K user documents would add hundreds of MB for no
  behaviour change.
- **Replay IP guard runs after `AppAuthGuard`**, not before: `src/guard-migration.spec.ts` (1b) requires
  auth first on every guarded route. The global per-IP `AppThrottlerGuard` still runs before both.
- **Benchmark timing is asserted only with `HEIST_BENCH=1`.** Inside Jest the sim runs about 10x slower
  (module sandbox), and under the parallel suite the machine load made any p95 meaningless; the spec
  always runs the plain-Node bench script (`src/user/heist/replay-bench.helper-spec.ts`) for correctness.
- **`replayDigest_unique` is declared after the `mongoose-unique-validator` plugin.** The plugin merges a
  partial index's `partialFilterExpression` into its pre-save lookup, so `{replayDigest: d}` became
  `{replayDigest: {$type: 'string'}}` and every second Heist save failed as "not unique" (found by the
  real-MongoDB spec). The index itself enforces uniqueness (E11000 -> 409).
- **`STAR_RULES` / `runStars` still exist in `catnip-heist/src/ui/levels/progress.ts`** (not my file).
  `server.test.ts` pins them equal to `src/sim/score.ts` on every input; see requests.

## Manual steps (not executed)

1. **Deploy order (plan F6): backend first**, because `liveGamePipe` uses `forbidNonWhitelisted` and an
   older backend would 400 every save that carries `outcome` or `replay`. **Then the migrations, then the
   client.**
2. Migrations, on a staging snapshot first, then production, from `backend/` with `MONGODB_URI` set:
   `npx migrate-mongo up` (dry run: prints counts and throws, nothing recorded), then
   `MIGRATION_APPLY=1 npx migrate-mongo up`. Check the grandfather report (`toUpdate`,
   `objectShapedSources`) and that no unlock is lost.
3. `backend/.gitignore` lists `/migrations`. The migration logic now lives in the committed
   `backend/src/user/heist/migrations/*.cjs` (the specs require those, so a clean checkout passes);
   the two files in `migrations/tokentails/` are thin wrappers that must still be added with
   `git add -f` (or recreated from their header) on the machine that runs the migrations.
4. CI: add `npm run vendor-sim:check` to the catnip-heist job (the Heist vitest also runs it through
   `src/sim/__tests__/vendor.test.ts`), and optionally a job with a MongoDB service running
   `LIVE_SPEC_MONGO_URL=mongodb://localhost:27017 npx jest src/user/heist/heist-mongo.spec.ts`.
5. Production needs `TRUST_PROXY` set behind the load balancer, or the per-IP replay bucket (like every
   per-IP limit) is shared by all clients (existing BACKEND.md:351 issue). The backend logs an error at
   startup when `NODE_ENV=production` and `TRUST_PROXY` is unset, and in that state **every Heist replay
   is refused with 503** (plain score saves are unaffected), so a missing `TRUST_PROXY` shows up as broken
   Heist saves, not as an open replay queue. Outside production the bucket falls back to
   `${ip}:${userId}` for private/loopback addresses.
6. **Whenever the sim changes** (`SIM_VERSION`, a level file, a cat in `public/assets/manifest.json`):
   re-run `npm run vendor-sim`, **deploy the backend first, then the Heist site**. Gate the Pages job
   (`.github/workflows/catnip-heist-pages.yml`, CI owner) with
   `npm run vendor-sim:check-remote -- https://<backend>` before publishing: it exits 1 unless
   `GET /user/catbassadors/heist-sim` serves this exact `bundleSha256`.
   Done by the W3 integrator: the Pages workflow has a `backend_url` input (default
   `https://api.tokentails.com`) and a "Backend serves the same sim" step before the build. It fails
   until the production backend with `/heist-sim` is deployed, which is the intended order.
