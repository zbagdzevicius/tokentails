# 4b: Catnip Heist in the shell (G2 layers 1 and 3, G14 picker, F9 Heist analytics)

Founder item 2 ("Catnip Heist hidden"). Nothing committed, nothing deployed, nothing uploaded.

## What was built

### Layer 1: discovery and host
- `client/pages/heist.tsx`: `FirebaseAuthProvider authMode="optional"`, `SeoHead` (title, description,
  OG, canonical `https://tokentails.com/heist`), and `HeistHost`. The iframe
  `/heist-game/index.html?embed=1` is in the server HTML (checked by the e2e and by
  `check-app-export.mjs`). The Heist is a static three.js build with no Phaser or Stellar code, so no
  `next/dynamic` is needed.
- `client/components/heist/`:
  - `hostBridge.ts`: host side of `shared/heist-bridge.ts`. `hello` every 500 ms for at most 10 s;
    a late `ready` (the Heist also announces `ready` once, unasked, when it installs) still
    connects. After `ready`: `session`, and `save-result`, `pause`, `resume` as they happen; a pause
    asked before `ready` is re-sent on `ready`. Source and origin checks are hygiene only: the iframe
    is same-origin, so it is **not a security boundary**; the backend replay is what makes saves
    trustworthy.
  - `suspension.ts`: registers a stand-in "game" in `lib/game/gameRegistry`, so every GameModal
    (the AuthSheet included) pauses the Heist and the iframe gets `inert`. No registry change.
  - `session.ts`: server progress from `heistScore`/`heistStars`, safe-area inset probe (insets are
    0 inside an iframe), frame URL (QA params forwarded only in development or E2E builds),
    `heist_open {from}`.
  - `HeistSaveChip.tsx`: the save chip, `role="status"`, always mounted. Phones: top centre; md+:
    top right, clear of the results banner.
  - `HeistHost.tsx`: wires it together, plus the claim prompt (GameModal).
- `client/next.config.js`: `/heist` is no longer redirected; `/heist/index.html` -> `/heist`
  (308); `/heist/:path+` -> `/heist-game/:path+` (308); `/heist-game` -> its index.
- `client/scripts/check-app-export.mjs`: requires `heist.html` (with the iframe in its HTML),
  `heist-game/index.html` and the old-path forwarder pointing at `/heist`.
- Heist embed mode, `catnip-heist/src/embed/`: `?embed=1` only counts inside a frame; forces seed 1;
  ignores `?replay=` without `qa=1`; applies insets as `--ch-sat/--ch-sar/--ch-sab/--ch-sal` on the
  UI root and `--tt-inset-*` on the document; merges server progress
  (`ProgressStore.mergeServer`: never lowers, won OR, best max, stars OR); host `pause` pauses a
  running heist (resume stays the player's tap). UI: "Token Tails" exit on the title, "Sign in to
  keep your stars" on results while signed out. Embedded first-time players go from START straight
  into level 1 (no level select), so the entry is PLAY, START.

### Picker (GameSelectModal) and G14

- "CLASSIC" tag on Purrsuit; "No new levels for now..." removed (#94).

  No `scale-90`. Width `min()`-bounded; height bounded by the GameModal container (dvh minus safe

  from the app origin, not the CDN (no upload needed).

### Layer 3: saves (F5.7 optional)
- `USER_API.saveMatchDetailed(match)`: `{ ok, status, code, body?, retryAfter? }`, no
  `waitForLocalStorageKey`, never throws, no 429 retry of its own, 428 handled once by the wrapper,
  403 never opens the sheet. `saveMatch` is unchanged byte for byte.
- `components/heist/heistSaves.ts` (`HeistSaver`):
  - Only won runs are posted (`HEIST_NOT_WON` otherwise). Body: `{ type: 'CATNIP_HEIST', replay, platform }`.
  - Firebase user (anonymous included): posted at once under that uid; no queue entry when it saves.
  - No Firebase user: queued in `tt.heist.queue.v1` as a device run (owner `null`).
  - Device runs leave the device only after "Add N heists played on this device to your account?"
    (guests: "...to your game progress?"); "Not mine" deletes them (#18). Confirming tags them with
    the uid first; a run tagged for uid A never drains for uid B.
  - 2xx and 409 done; 400 `HEIST_SIM_VERSION` purges every queued run of that version with a visible
    message; other 400 and 413 dropped; 401/403/428 kept; 429, 5xx and network back off
    (5 s, 15 s, 45 s ... 10 min, Retry-After respected). A newer `simVersion` from the Heist purges
    older queued runs with the same message.
  - Heist runs consume no lives (#17): the only write is `/live`.
- Referral: `/heist?ref=X` is captured by the optional provider (existing `pendingRef`) and sent on
  promotion; unit test covers the /heist path.

### F9 analytics mirror
- `shared/analytics-core.ts` (synced to client and heist): event names and areas, consent key,
  PostHog host, the scrubber, and the session budget (cap and per-code dedupe).
- `client/analytics`: `events.ts`, `scrub.ts`, `consent.ts`, `client.ts`, `errors.ts` re-export or use
  the core; behaviour unchanged (existing tests green).
- `catnip-heist/src/analytics/`: sends only when `tt-analytics-consent` is `granted` at send time,
  only `heist_open` (standalone loads) and `heist_run_complete`, no person profiles, scrubbed flat
  properties. Imported behind the same build flag as the crash module: a `VITE_HEIST_BUILD=replay`
  build contains no analytics module (checked: no consent key, endpoint or PostHog host in the bundle).
- `catnip-heist/src/app/crash.ts` now uses the shared scrubber, consent check and budget (the copied
  rules are gone).
- Host page events: `heist_open {from}`, `heist_save {status}`, `heist_signin_prompt {from}`,
  `heist_guest_claim {status}`.

## Review fixes (second pass)
Every finding was verified; all thirteen were valid and are fixed except where noted.
1. **Picker X over ABOUT ME at 844x390.** Short landscape (`max-height:520px`) caps the frame at
   `min(50rem, 100vw - 13rem)`, so its post clears the lobby's right column; the spec passes at all
   four viewports. Card titles there use the compact label (the pixel button did not fit four across).
2. **QA hooks in production.** `src/app/qa-build.ts` `QA_BUILD = DEV || VITE_HEIST_QA === '1'`;
   `main.ts` imports `./app/qa` dynamically only under it, and `App.qaStep/qaFeed/qaSetInput` are
   no-ops without it. Checked: the shipped `client/public/heist-game` bundle has no `__heist`,
   `playSolution` or QA driver bodies, and `?qa=1` installs nothing (asserted in the client e2e).
   The Heist e2e build sets `VITE_HEIST_QA=1` (`catnip-heist/playwright.config.ts`); the client e2e
   builds a QA copy into `client/test-results/heist-game-qa` once per run and serves it for
   `/heist-game/*` only in the tests that play the bundled solution.
3. **Anonymous runs stranded on sign-in.** Runs queued under an anonymous uid are tagged `anon`.
   When a different uid is signed in, `HeistSaver.releaseGuestRuns()` turns them back into device
   runs and the claim prompt asks again (reopened even if dismissed earlier). Never released before
   Firebase reports a user, and a registered account's runs are never released. Unit tests added.
4. **3 taps.** See the own call above; the e2e counts the taps and checks the HUD is up.
5. **Notch check.** Phones emulate a 47/34 px safe area with CDP
   `Emulation.setSafeAreaInsetsOverride`, assert `env(safe-area-inset-top)` is 47 px, then measure
   the X (below 47) and the frame (above the home indicator).
6. **axe.** Full rule set on the dialog, no exclusions; passes at all four viewports.
7. **Modifier clicks.** Ctrl/Cmd/Shift/Alt and non-primary clicks are left to the browser; the link's
   `href` is `/heist?from=picker`.
8. **`heist_guest_claim`** is sent after the claim, `ok` only when every claimed run left the queue
   (`offline`/`error` otherwise).
9. **409 for another account's log.** `saveMatchDetailed` passes the 409 body's `mine` on; the chip
   says "Already saved" for the caller's row and "This heist is already saved on another account."
   (rust tone, bridge `rejected`, `heist_save {status: rejected}`) for someone else's. **Needs task
   3b**: the backend 409 body does not carry `mine` yet, so today every 409 shows the neutral
   "Already saved." (never "Heist saved").
10. **Flaky claim flow.** Waits for the results' sign-in button, and targets the AuthSheet by name
    ("SAVE YOUR CAT").
11. **`mergeServer` prototype keys.** `__proto__`, `constructor`, `prototype` are always skipped.
12. **`scale-[0.78]`.** Phones get a compact title label at real size; the pixel button only from md
    and 521 px tall. No transform shrink left on the cards.
13. **OG image.** `/heist` uses `client/public/game-select/heist-og.jpg` (1200x630, the Heist title
    screen) with width, height and alt.

## Known limitations
- `/heist` keeps page pinch zoom (skyScope only locks `/game`); the host sets `touch-action: none`
  and the Heist document has its own, but the viewport lock is skyScope's owner's call.
- QA forwarding (`?qa=1`) swaps the iframe src after hydration, so the frame loads twice in
  development and E2E builds; production never forwards.
- Heist audio keeps playing under the host pause (the Heist's own pause menu does the same).
- The claim prompt asks once per page view; closing it with X asks again on the next visit.
- A 409's owner needs the backend's `mine` field (task 3b); until then the chip is neutral.
- The client e2e QA build takes about a second on the first run and is cached by source mtime in
  `client/test-results/heist-game-qa`.
