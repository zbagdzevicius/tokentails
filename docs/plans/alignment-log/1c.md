### GameModal behaviour

- Scrim `bg-tt-night-950/70` + `backdrop-blur-[4px]`, `lowfx:backdrop-filter-none`,
  `reduced-transparency:` no blur and `/90`. Frame drop shadow and glow dropped under `lowfx`.
- Title: `font-primary` (Passion One) uppercase, `text-tt-gold-400`, gold-shadow bevel;
  `aria-labelledby` from Radix. No description means no `aria-describedby`.
- Focus: on open the dialog itself is focused (no mobile keyboard pop) unless `initialFocus`.
  On close focus returns to whatever had focus at open time. Radix only restores focus to a
  `Dialog.Trigger`, and our modals open from state, so GameModal does this itself.
- `dismissible={false}`: no X; Esc and scrim prevented. `canClose={false}`: X visible,
  `aria-disabled`, greyed; Esc and scrim prevented; `onOpenChange(false)` never fires.
- `modal={false}`: no Radix overlay (an identical plain scrim is rendered), no focus trap;
  `allowOutside(target)` stops outside pointer/focus from dismissing.
- Children are inside `ModalBoundary` (1e) with `onClose` when closable.
- `suspendGame` (default true) calls `useSuspendGame(open)`.
- Surfaces: `panel` (PixelFrame, header fixed, body scrolls), `sheet` (bottom sheet on phones with a
  safe-area bottom pad, centred from `md`), `art` (no frame, sr-only title, X `outside`).
- Enter animations only; `motion-reduce:animate-none`.

### Suspension (F3.5)

While any suspension is held, every registered game gets: `input.keyboard.enabled = false`
(manager), each scene's keyboard plugin `enabled = false` plus `resetKeys()` (held keys would keep
the cat running), `disableGlobalCapture()`, `loop.sleep()`, and a pause of the sounds that were
playing (`getAllPlaying()`; `pauseAll()` as fallback). Release restores the saved values
(`enableGlobalCapture()` only if capture was on; `loop.wake(true)` only if it slept it; resumes only
the sounds it paused). Suspensions nest. Games registered during a suspension are suspended at once;
a game still booting is put to sleep after its first `poststep`.

Found and handled: Phaser defers `game.destroy()` to the next loop step, so destroying a game while
its loop sleeps would never tear it down (canvas and WebGL context leak). The registry wraps
`destroy` to wake the loop first, and clears the entry at once (and again on Phaser's `destroy`).

## Second review fixes

1. **Game created under an open modal kept its loop running (fixed).** A real `new Phaser.Game()` on
   a loaded page is booted at once (`isBooted` true) but its loop starts only after the default
   textures load (`Game.boot` -> `texturesReady` -> `start`, which sets `isRunning`). The registry
   only deferred the sleep for `isBooted === false`. It now also defers when `isRunning === false`
   (`isRunning` added to `RegistrableGame`) and sleeps after the first `poststep`. The old test used
   `running: true`, which real Phaser never has at that point; a new test uses
   `{booted: true, running: false, isRunning: false}`.
   Also, scenes keep loading while the loop sleeps (the loader is event driven), so music started in
   `create()` played under the modal. While suspended, the registry wraps `game.sound.add` (which
   `sound.play(key)` also goes through) and pauses each new sound on its `play` event; those sounds
   resume with the rest and the wrapper is removed on release (only if still ours). Phaser's sound
   manager emits no manager-level `play` event, hence the wrapper.
2. **Filter on the PixelFrame made the panel the containing block for fixed children (fixed).** The
   drop-shadow and glow moved from the frame's `className` to a new PixelFrame `shadowClassName`,
   applied to an `aria-hidden` span wrapping the three clipped layers and the glint. The content box
   and its ancestors carry no filter or transform (the modal-in animation ends at `transform: none`),
   so `fixed inset-0` overlays and `CloseButton placement="viewport"` size to the viewport on every
   device. Test added.
3. **Pre-boot registration left the keyboard dead (fixed).** For `isBooted === false` the keyboard
   part (manager, plugins, capture) is no longer applied at suspend time; it is applied after the
   first `poststep` if the suspension is still held. If the modal closes before that, nothing is
   touched. Two tests.
4. **Destroy while suspended resumed sounds for a frame (fixed).** `patchedDestroy` empties the
   paused-sound list (and the `pauseAll` flag) before unregistering, so nothing is resumed. Test.
5. **X last in the tab order (fixed).** GameModal renders the CloseButton before the header (panel
   and sheet) and before the body (art). It is absolutely placed, so nothing moves. Test.
6. **Stale log line (fixed):** item 2 above.
7. **Two exports named `GameModal` (logged, outside 1c).** `components/ui/GameModal` (component) and
   the `GameModal` enum in `@/models/game` (imported by `components/shelter/Shelter.tsx:22` and
   others). Request below.
8. **CloseButton default placement (accepted deviation, unchanged):** see Decisions; task 4d flips it.
9. **Follow-up to item 2, found in the browser re-check (fixed).** The modal and sheet enter
   animations used fill mode `both`. A filled end keyframe interpolated to `transform: none` computes
   as `translateY(0)` (`matrix(1, 0, 0, 1, 0, 0)`), and Dialog.Content stayed the containing block of
   `position: fixed` children after the animation ended. `tt-modal-in` and `tt-sheet-in` now use
   `backwards` (the start state shows on the first frame; nothing stays applied after). Checked at
   :3001 on the `/game` welcome sheet: no ancestor of the frame has a filter or transform. A test in
   `__test__/design-tokens.test.ts` covers it.

## Known bug fixed: Phaser key capture swallowed typing (F3.5, G9)

`Catbassador.ts:167-175` added W, A, D, Z, Q with capture on, and `createCursorKeys()` captures space
and the arrows. Phaser's KeyboardManager listens on `window` and calls `preventDefault()` on
captured keys, so those letters and space never reached any input on the page while a game ran.

Fix, two layers:
1. `Catbassador.ts`: letter keys added with `enableCapture = false`. Space and arrows stay captured
   (no page scroll, no re-click of a focused button when jumping).
2. `gameRegistry.ts` field guard: a capture-phase `window` listener turns the registered games'
   keyboard managers off for any key event whose target is an input, textarea, select or
   contenteditable, and back on after Phaser's listener (a bubble listener added during the event,
   plus a timer fallback). The game neither moves nor `preventDefault`s while you type, in any
   field, modal or not. A GameModal also suspends the keyboard entirely.

Verified against real Phaser 4 rc.5 in a scratch bundle (not committed): without registration,
typing "wadzq " into an input gave "" and the scene saw 26 key events; with registration it gave
"wadzq ", the scene saw none, `d` outside the field still reached the scene, and during a
suspension the loop made 0 steps and saw no keys, resuming normally on release.

`docs/CLIENT.md` "Known issues" never listed this bug, so there is no line to remove there (not my
file anyway); the plan's F3.5 entry is the record.

  writes them.

  still honours the legacy call shape so the 15 unmigrated callers do not move: `absolute` means

  `placement`, delete `absolute` and make `placement` default to `"inside"`.

  z-[60]); `sticky` keeps its old `z-[90]`; `viewport` uses `z-modal-nested`. The `z-[200000]` is gone.
- lowfx detection also treats Capacitor `getPlatform() === "android"` as low-fx.
- GameModal focuses the dialog, not its first control, on open (avoids popping the phone keyboard).
- The axe check runs in jest (`axe-core` in jsdom, contrast off since jsdom has no layout); a scratch
  Playwright run of a bundled demo with `@axe-core/playwright` (contrast on) found 0 violations at
  1440x900 and 390x844. No test-only page was added under `pages/`.
