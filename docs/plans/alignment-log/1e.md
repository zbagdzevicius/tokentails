## What was built

### Boundaries (`client/components/errors/`)

| File | Level | Where | Fallback |
|---|---|---|---|
| `RootBoundary.tsx` | root | `pages/_app.tsx`, outside every provider | Full screen at `z-index: 600` (F3 `system`), RELOAD + TRY AGAIN |
| `PageBoundary.tsx` | page | `layouts/MainLayout.tsx` inside the providers, `key` = `router.pathname`, `resetKey` = path without query | Full screen at `LAYERS.system - 10` (590), TRY AGAIN + RELOAD |
| `SceneBoundary.tsx` | scene | `components/game/Game.tsx`, one per Phaser mount (HOME, SHELTER, CATNIP_CHAOS, PIXEL_RESCUE, MATCH_3) | Full screen between `LAYERS.gate` and `LAYERS.modal` (90: above the canvas and run gate, below lobby modals), TRY AGAIN (remounts through a fresh key) + BACK TO MENU (`setGameType(null)`, the lobby) |
| `ModalBoundary.tsx` | modal | For 1c's GameModal | Inline card in the modal |
| `SectionBoundary.tsx` | section | For 3f's landing sections (`pages/index.tsx` not edited) | Renders nothing (or a `fallback` prop) and reports |

- `ErrorBoundary.tsx` is the one class they share. It reports `app_error` with the code
  `<level>_crash:<name>` (for example `scene_crash:match_3`) and resets on `reset()` or a `resetKey` change.
- `CrashPanel.tsx` is the fallback UI. It uses no context, only inline styles plus a scoped
  `tt-crash-*` stylesheet string. The mascot comes from `/public/mascots/actions/napping.webp`, not the
  CDN, and the image hides itself if it fails to load. Colours are the night palette (`#0b0820` sky,
  coin `#ffc93c`, cream `#fcecbb`). The screen variant has `role="alertdialog"` and the inline variant
  `role="alert"`, both labelled. Focus moves to the primary button. Buttons are at least 48 px tall
  and sit side by side when they fit, otherwise one full-width button per row. Motion stops under
  reduced motion.
- `copy.ts` holds the copy, decision #89 (see "Decisions applied" below).
- `reload.ts`: `reloadApp()`. App builds (`NEXT_PUBLIC_IS_APP`) call `location.assign('/')`, the
  route Capacitor boots `index.html` on, and AppRouteRestore handles routing from there. The web
  calls `location.reload()`.
- `crash-probe.tsx`: forced-crash hooks, live only when `NEXT_PUBLIC_E2E=1`.
  `?__crash=root|page|scene|modal|section` throws inside that boundary until it is reset.
  `?__crash=listener` makes the next GameEvents listener throw once.
- `SceneBoundary` also listens for `tt-scene-stall` (`errors/events.ts`) from the crash guard and
  shows the scene fallback. That error is marked `alreadyReported`, so it is not counted twice.

### Phaser crash guard (`client/components/Phaser/events.ts`)

- Every GameEvents listener is wrapped in try/catch: `use()` hooks and `addEventListener`, with a
  WeakMap so `removeEventListener` finds the wrapped function. A throw is reported as
  `listener_error:<event>` and the other listeners still run.
- `createStallWatchdog()` and `installPhaserCrashGuard()`: armed on `GAME_LOADED`, listening to the
  game's `poststep` heartbeat. Phaser only schedules its next frame after the current step returns, so
  an exception in `update` freezes the canvas without a sound.
  - The watchdog reports `scene_stall` after 8 s without frames while the page is visible and the game
    is not paused (`isPaused`, `loop.running === false`).
  - It resets on `visibilitychange`, `pageshow`, `focus` and Capacitor `App` `resume` (native only).
  - It skips a check when its own interval was throttled (background tab or device sleep), and it is
    disarmed when the game is destroyed.
  - Startup is watched too (review round 2): the guard finds each new game through
    `lib/game/gameRegistry` `getRegisteredGames()` and, after the game's first `poststep`, arms a
    15 s startup watchdog (Phaser keeps stepping while it loads). `GAME_LOADED` switches to the 8 s
    one. A scene left in Phaser's CREATING status on two checks in a row (its `create()` threw from
    a loader callback, so the loop keeps running) is reported as `scene_start_failed` and shows the
    scene fallback. A suspended registry (modal open) counts as idle.
  - Match 3 never sends `GAME_LOADED`, so it is watched with the 15 s startup limit.
- `installWindowErrorReporting()` (installed in MainLayout): `window_error` only when
  `event.filename` is same-origin. `unhandled_rejection` only when the first stack URL is same-origin.
  Extensions, wallets and "Script error." are ignored.

### Telemetry (`client/analytics/`)

- `scrub.ts` is pure, with no imports, ready to move to `shared/analytics-core.ts` (task 4b). It
  removes:
  - emails
  - JWTs, including `fb`-prefixed tokens
  - Stellar S seeds and G, C and M addresses
  - `0x` hex values
  - ObjectIds and long hex
  - `+` phone numbers and runs of 9 or more digits (isikukood)
  - hyphenated personal codes (`3800108-5718`) and space-grouped phone numbers (`5512 3456`)
  - URL query strings and fragments
  - quoted names

  Quoted identifiers are kept (`'sort'`, `"token-tails"`, `'GAME_LOADED'`). Stacks are cut to 8
  frames with the origin removed. Context values are flat primitives only (at most 12 keys).
- `errors.ts`: `createErrorReporter()` and `buildAppErrorProperties()`. Reports go through
  `analytics.track` only, so the existing consent gate applies. Nothing is counted before consent or
  without a key. Limits are at most 5 reports per tab session and one per code, with the counts in
  sessionStorage (`tt-app-error-session`) so RELOAD cannot loop them. The reporter never throws and
  never calls `posthog.captureException`. The existing `capture_exceptions: false` init flag is
  unchanged.
- `index.ts`: `reportAppError(code, error, context)` plus the new exports.
- `events.ts`: one typed catalog with every row of the F9 table (entry, identity, onboarding, runs,
  heist, impact, health) and the existing `game_quit`. It also has `ANALYTICS_EVENT_AREAS`, typed
  property shapes per event (never a user id, email or cat name; `starter_named` carries only
  `length`), `buildEvent(name, props)` and the `AppErrorProperties` shape.
- The overstated Heist parity comment is corrected. It now says the Heist sends none of these events
  today; its only telemetry is the G13-H crash report, and the `heist_*` names are the ones it will
  send after 4b.

### G13-H Heist crash fallback (`catnip-heist/src/app/crash.ts`, `src/main.ts`)

- Behaviour:
  - A boot failure or an uncaught same-origin error shows a night overlay: "Something went wrong.
    Your cats are safe." with RELOAD, focused, `role="alertdialog"`, Cat Paw title.
  - Same-origin unhandled rejections only report (an asset promise failing is often recoverable).
  - Reports go out only when localStorage `tt-analytics-consent` is `granted` (same origin as
    tokentails.com under `/heist`), at most 5 per session and one per code.
  - Reports go through `navigator.sendBeacon` to PostHog's capture endpoint, with an anonymous
    per-tab id and `$process_person_profile: false`.
  - Nothing is sent unless `VITE_POSTHOG_KEY` is set at build time. `VITE_POSTHOG_HOST` is optional
    and defaults to the EU host.
  - `?replay=` sessions show the overlay but never report.
- Build flag: `VITE_HEIST_BUILD=replay|verify` compiles the module out. Checked in this task: a
  `VITE_HEIST_BUILD=verify vite build` bundle has no fallback copy, and a normal build has it.
  Replay and verify builds keep a plain `<pre>` for the developer, now written with `textContent`
  instead of `insertAdjacentHTML`.
- The scrub rules now come from `shared/analytics-core.ts` (task 4b), read by the Heist through
  `src/shared-contracts/analytics-core.ts`. `client/analytics/scrub.ts` only re-exports them, so the
  two products scrub with one rule set.

## Known limitations

- The E2E hooks are inert in normal builds, but because Next leaves an unset `NEXT_PUBLIC_` variable
  as a runtime lookup, they are not removed from the bundle as dead code.
- A game whose boot throws before its first step (inside `new Phaser.Game`) is not caught by the
  watchdog; the mount's own error reaches the SceneBoundary only if it throws during render.
- The scrubber keeps a bare lowercase word after a browser TypeError word (`reading 'fluffy'`),
  since property names look exactly like that. After our own words (`key`, `event`, `scene`,
  `texture`, `animation`, `atlas`) the word must look like code or it becomes `[name]`.
- Old native builds keep crashing the old way until the next store release. The G13 backend hotfix
  is what protects them.
- Heist reports need a PostHog key in the Heist build. Without one, the overlay still works and
  nothing is sent.

## Review round 1 fixes

1. **Heist: a single error no longer ends the run** (medium, valid). A lone same-origin window
   error is now only reported. The overlay shows only for:
   - a boot failure;
   - a burst of 3 or more errors within 2 s (`heist_error_burst`);
   - the frame heartbeat (`App.lastFrame`) not moving for 5 s or more while the page is visible
     (`heist_frame_stall`).

   A hidden tab, or a throttled timer (a gap of more than 3 s between checks), restarts the count.
   Playwright on :5173: one error leaves no overlay, a burst shows it, and 18 s idle shows none.
2. **Stalled Phaser game is torn down** (medium, valid). `installPhaserCrashGuard`'s stall handler
   now calls `destroy(true)`, then `runDestroy()` when `pendingDestroy` is set
   (`teardownStalledGame`). `runDestroy` emits `destroy`, which also unregisters the game from
   `gameRegistry`. I rejected the suggested `!game.loop?.running` gate for the mount cleanups,
   because a stalled Phaser loop keeps `running === true`.
3. **Lowercase quoted names** (valid). A quoted string is kept only right after a code word:
   reading, setting, property, evaluating, execute, method, function, module, parameter, argument,
   field, key, event, scene, texture, animation or atlas. It must also contain no spaces. Everything
   else becomes `[name]`. I kept `key`, `event`, `scene`, `texture`, `animation` and `atlas` in the
   list beyond the suggested three because our own messages and Phaser's use them and the existing
   vectors rely on them. Both scrubber copies are updated.
4. **Opaque tokens, `did:` ids, IBANs** (valid). New rules for `[token]`, `[did]` and `[iban]`
   (spaced or not). The token rule runs last. It spares a run followed by a file extension, so
   bundle names with content hashes survive. Both copies are updated.
5. **Capacitor iOS origin** (valid, checked with node: `new URL('capacitor://localhost/x').origin`
   is `"null"`). `isSameOrigin` in both copies compares protocol and host. The same bug was also in
   the reporter's stack-origin strip: `location.origin` of `"null"` would have deleted every "null"
   from stacks. `errors.ts` now uses `pageOrigin()` (scheme plus host). Unit tests cover
   `capacitor://localhost`. It still needs a check on a device.
6. **Stack line and column after a query** (valid). The query rule leaves a trailing `:line:col`
   in place: `game.js?[query]:10:5`.
7. **Nits** (valid):
   - The `guardListener` comment is corrected: `dispatchEvent` does run the rest.
   - `CrashPanel` has a `modal` prop. Root and page fallbacks keep `aria-modal` and now trap Tab.
     The scene fallback passes `modal={false}` (no `aria-modal`).

8. **Unreported App.ts edit** (valid). Recorded above; the getter stays.
