# Mobile Apps (Capacitor)

The iOS and Android apps wrap the static export of the Next.js client with Capacitor 7. Both use
the same app id and version.

| Item | Value |
|---|---|
| App id | `com.tokentails.app` |
| App name | Token Tails |
| Version | 23.0 (build 23) on both platforms |
| Web dir | `out/` (static export) |
| Orientation | Landscape only on phones |
| Stores | Google Play `com.tokentails.app`, App Store id `6745582489` |

Configuration lives in `client/capacitor.config.ts` and is mirrored into
`android/app/src/main/assets/capacitor.config.json` and `ios/App/App/capacitor.config.json` on
sync. The server block sets `androidScheme: "http"` with cleartext allowed.

## Plugins

| Plugin | Use |
|---|---|
| `@capacitor-firebase/authentication` | Google and Apple sign-in with `skipNativeAuth: true`; the web SDK then receives the credential |
| `@capacitor/app` | App state and URL events |
| `@capacitor/browser` | External links |
| `@capacitor/clipboard` | Share modal copy on native |
| `@capacitor/status-bar` (`~7.0.6`) | Night status bar: `Style.Dark` (light text) everywhere, the night background on Android API 34 and lower (`components/native/NativeChrome.tsx`, `statusBar.ts`; failures report `native_chrome_error`) |
| `@capacitor/keyboard` | `resize: Body`, `resizeOnFullScreen: true`, so the Meet your cat nameplate stays above the keyboard |
| `@capacitor/haptics` | Soft death, hard death and first clear feedback (decision #70), lazy-loaded, native only |

Core, Android, iOS and the CLI are pinned to `~7.2.0`. Android uses
`adjustMarginsForEdgeToEdge: "auto"` (supported from Capacitor 7.2).

`@capacitor/core`'s `Capacitor.getPlatform()` tags every score save (`platform` on the `/live`
body and the `Game` row) and every analytics event as `ios`, `android` or `web`. Analytics is
consent-gated and off unless `NEXT_PUBLIC_POSTHOG_KEY` is set for the build (see CLIENT.md,
"Analytics").

## Build flow

```bash
cd client
npm run build:app          # next build with .env.app; static export to out/
npm run check:app-export   # fail if out/index.html or a key route is missing
npm run app:sync           # capacitor copy + sync into android/ and ios/
npm run app:android        # build:app, check, sync, open Android Studio
npm run app:ios            # build:app, check, sync, open Xcode
npm run app:android:run    # run on device with live reload
npm run app:ios:run
npm run app:assets         # regenerate icons and splash from resources/logo.png
```

`app:assets` uses the night background `#0b0820` for icons and splash in both light and dark
(decision #45), and a 0.4 logo scale. Its input `client/resources/logo.png` (square, transparent) is
generated by `npm run icons:build` from `client/resources/source/logo.png`, together with the opaque
1024 App Store icon `client/resources/store/app-store-1024.png` (no alpha). The native icon and splash
ship with the next store submission (decision #95).

`.env.app` must set `NEXT_PUBLIC_IS_APP`. The flag switches `next.config.js` to
`output: "export"` (and drops its server redirects), turns off ISR and on-demand dynamic pages,
skips robots and sitemap extras, hides ad slots, hides web checkout, and enables app-only UI.
Web builds are unchanged.

### Static export routes

A static export has no server, so the web-only dynamic routes (`/cats/[cat]`,
`/feed/[category]/[article]`) emit no pages in app builds. App links go to client routes that read
the slug from the query string instead: `/cats/view?id=<id>` and
`/feed/article?category=<slug>&slug=<slug>`. `catPath` and `articlePath` in `api/routing.ts` pick
the right form, and `webPath` maps either form back to the canonical website URL for sharing.
Capacitor serves `index.html` for any extensionless path, so a full page load (a plain `<a href>`,
`window.location`) boots the homepage bundle whatever the URL says. `components/AppRouteRestore.tsx`,
mounted in `pages/_app.tsx`, then routes client-side to the page the URL names; prefer `next/link`
to avoid the extra load. It maps old-form `/cats/<id>` and `/feed/<category>/<slug>` paths to the
query-param routes (`appPath` in `api/routing.ts`), and tries each path once per session, so a path
the export cannot serve lands on the homepage instead of reloading forever.

`npm run check:app-export` (`scripts/check-app-export.mjs`) fails unless `out/` contains
`index.html` loading the Next bundle, `_next/static/`, and the key routes (`404`, `game`, `cats`,
`cats/view`, `feed`, `feed/article`, `packs`, `box`), plus `heist.html` with the Heist iframe in its
HTML, `heist-game/index.html` loading `/heist-game/build/`, and the `heist/index.html` forwarder to
`/heist`. `app:ios:ci` and `app:android` run it before syncing. App builds read the committed impact
baseline (`public/impact/snapshot.json`); refresh it from production before every app build
(`IMPACT_SOURCE_URL=https://<prod-api>/impact node client/scripts/snapshot-impact.mjs`).

App builds use the app label set for impact claims: no chain, wallet, USDC or explorer wording;
proof opens web `/impact` through `@capacitor/browser` (decision #32). Inside the app the Heist always
shows pre-launch treat copy, because its host is not in the Heist's API host map.

### Purchases

Store rules require in-app purchase for digital goods, and IAP (RevenueCat) is deferred. App
builds therefore hide every Stripe and Stellar checkout: `Payment`, `StripePayment`, and
`Web3Transfer` render `AppCheckoutNotice` ("Purchases are not available in the app yet.") and
Stripe.js is never loaded; the codex hides its PET ART tab (the paid portrait flow) and the flow
hides its price, card and web3 toggle; the portrait preview page hides its purchase options; the
mystery box hides its price; the packs screen shows the packs without prices or the purchase tag,
and picking one does nothing. Free boxes still open.

## Android

- `android/variables.gradle`: minimum SDK 23, compile and target SDK 36, version code 23, version name 23.0, Java 21. Building needs Android SDK Platform 36 installed. The Android Gradle Plugin is 8.7.2, which officially supports compile SDK up to 35 and warns on 36.
- Manifest: single permission `INTERNET`. Main activity is `singleTask`, landscape, exported. No app links or custom scheme intent filters.
- Release build type has minification disabled.
- `google-services.json` is present at `android/app/` and applied conditionally by Gradle. It is tracked in git.
- Splash and icons for all densities including night variants are generated by Capacitor Assets.
- A built `android/app/release/app-release.aab` is committed. It should not be.
- Signing uses a keystore at `client/tokentails-keystore`, which is gitignored since March 2026.

### Play Store release

Fastlane lane `internal` in `client/android/fastlane/Fastfile` runs a clean release bundle and
uploads it to the internal track without metadata, images, or changelogs.

```bash
export ANDROID_PACKAGE_NAME="com.tokentails.app"
export GOOGLE_PLAY_SERVICE_ACCOUNT_JSON_B64="<base64 service account json>"   # or GOOGLE_PLAY_SERVICE_ACCOUNT_JSON_PATH
./client/scripts/android-play-release.sh
```

The script validates the variables, decodes the key to a temp file, runs `bundle install` in
`android/`, and invokes the lane. Ruby and Bundler are required on the runner. Details in
`client/docs/ANDROID_GOOGLE_PLAY_AUTOMATION.md`.

## iOS

- Xcode project at `ios/App/App.xcodeproj`, deployment target iOS 14, CocoaPods with frameworks.
- Bundle id `com.tokentails.app`, marketing version 23.0, build 23.
- Entitlements enable Sign in with Apple in debug and release.
- `Info.plist` declares a URL type for the Google sign-in callback scheme and declares supported orientations twice; the later declaration restricts iPhone to landscape and is the effective one. A stray top-level `CFBundleURLSchemes` key also exists.
- `GoogleService-Info.plist` is present at `ios/App/App/` and tracked in git.
- Podfile post-install disables code signing for resource bundle pods, a Firebase workaround.
- `LaunchScreen.storyboard`, the `Splash.imageset` PNGs and `AppIcon-512@2x.png` are night `#0b0820` (no alpha; `__test__/palette-native-chrome.test.ts` checks the PNG colour type).

## Native chrome (plan G6)

`capacitor.config.ts` sets `backgroundColor` (and the Android and iOS ones) to `NATIVE_BACKGROUND`
(`#0b0820`, the same as `THEME_COLOR`), `plugins.StatusBar` to `{style: "DARK", backgroundColor}` and
the keyboard plugin as above. Android resources: `values/colors.xml` `tt_night_900`, a night
`ic_launcher_background`, night `windowBackground` on every theme, and the Android 12+ system splash in
`values-v31/styles.xml`. The legacy splash PNGs were recoloured from coral to night. On Android 15
(API 35+, target SDK 36) the status bar colour call is a no-op (edge-to-edge is enforced), so the
night window background shows instead. `MainActivity.java` still forces immersive fullscreen, which
hides the status bar.

## Native release train (decision #90, not run)

Native changes are batched and ship together with the next store submission:

1. `npm run icons:build`, then `npm run app:assets`, then rerun `jest __test__/palette-native-chrome` (regenerating rewrites the icon files; the 1024 icon must stay RGB without alpha).
2. `npm run app:sync` (or `npx cap sync`) so `@capacitor/status-bar`, `@capacitor/keyboard` and `@capacitor/haptics` reach both native projects (the plugin class lists and the generated `capacitor.config.json` copies), then `pod install`.
3. Refresh `public/impact/snapshot.json` from production, `npm run build:app`, `npm run check:app-export`.
4. Device QA on Android 15+ and iOS: no white frame between splash and game, the night splash, the status bar style, no jump when immersive bars appear with `adjustMarginsForEdgeToEdge: "auto"` (decide immersive fullscreen versus edge-to-edge), the keyboard keeping the Meet your cat nameplate in view, haptics, Android back on the RunGate and the claim drawer, Sign in with Apple deletion with a fresh authorization code, `/heist` with notch insets, the `MobileControls` tap fix, safe areas in Paw Match.
5. Decide `zoomEnabled` (Capacitor's default keeps every native route unzoomable) and check that `/game` stays locked in WKWebView and Android WebView.
6. Store screenshots and preview videos (decision #54, from the capture pipeline once clips are re-rendered), age-rating answers after the catnip art and Heist copy, privacy labels (anonymous device id for guests, reCAPTCHA if App Check is on, PostHog analytics).
7. Bump the version numbers below and submit.

### Xcode Cloud

`ios/App/ci_scripts/ci_post_clone.sh` installs Node 20, Yarn, CocoaPods, and Fastlane through
Homebrew, runs `pod install`, then `npm ci` and `npm run app:ios:ci` from the client root to build
the web bundle and sync it before Xcode builds. The pre and post build scripts are stubs.

## Deep links

None are configured beyond the Google sign-in callback scheme on iOS. Referral links open the
website, not the app.

## Local device testing

`npm run dev:https` serves the client over HTTPS using certificates in the ignored
`certificates/` folder. The `ngrok` script exposes a LAN dev server on a fixed ngrok domain; edit
the hardcoded LAN address before use.

## Known issues

- Plain anchors (for example PLAY on the homepage) still cause a full reload in the app before `AppRouteRestore` routes to the page.
- Portrait marketing pages still show prices in app builds, although checkout is hidden.
- Firebase config files for both platforms and a release `.aab` are committed.
- Duplicate orientation keys and a stray URL scheme key in `Info.plist`.
- No universal links or Android app links, so shared URLs cannot open the app.
- The App Store privacy details and the Play data safety form do not list PostHog analytics, the anonymous guest id or App Check. Update them before shipping an app build with `NEXT_PUBLIC_POSTHOG_KEY` set or guests enabled.
- Fixed (task 3d, plan G6): the app icon, splash and launch screen used the coral `#fc8b6d` and the iOS launch screen was white; they are night `#0b0820` now (ships with the next store build).
- Fixed in code (task 4a, plan G3): no `@capacitor/keyboard`, so the iOS keyboard could cover form fields; configured, takes effect after the native sync.
- Installed native builds keep the old client code (no error boundaries, the old Shelter crash path) until the next store release; the backend storefront hotfix protects them meanwhile.
- `MainActivity.java` forces immersive fullscreen, so the status bar styling is mostly invisible on Android.
